0-6. seed_co_0007 に、companyQ に無い型を足す
　テストに使う型のうち、companyQ に無いもの（数字だけの文字列・小数の 1.0・バイト列）を足す。
　バイト列と 1.0 は、コンソールでは入れられない（バイト列は map になり、1.0 は整数の 1 になる）。
　なので、コンソールではなく、アプリの編集欄で足す。

　(1) コンソールで、seed_co_0007 から、前に足した bytes と dbl を消す。
　　（tel は、コンソールで型が string になっていれば、そのままでよい）
　(2) アプリでドキュメント詳細 seed_co_0007 を開く。
　(3) 編集欄の JSON の、最後の } の前に、次を足す（直前の行の最後に , を付ける）。
　　　"tel": "0901234567",
　　　"dbl": 1.0,
　　　"bytes": {"__firemint_type": "bytes", "base64": "AAEC"}
　　（tel が既にあれば、tel の行は足さない）
　(4) 「保存」→「書き込みの確認」「companyQ/seed_co_0007 を上書きします」→「実行」→「保存しました」。

　【Firestore】tel が string、bytes がバイト列（型の表示が blob。map ではない）。
　　　　　　もとからあるフィールドは変わっていない。
　　　　　　dbl は値の表示が 1 だが、型の表示（項目にマウスを当てる）が double。
　【端末】右上の読み直し（↻）で開き直すと、dbl が 1.0、
　　　　　bytes が {"__firemint_type": "bytes", "base64": "AAEC"} と出る。

googleの権限切れが発生。
バックグランドで1時間切れの再取得に失敗している

→　修正済 / 未テスト

自動で取り直しているか

バックグラウンドで定期的に取り直す仕組みはありません。
Firestore への問い合わせが権限エラーになった時に、1 回だけ取り直してやり直す作りです。

何が失敗しているか

取り直しの処理（ensureCloudAccess）は、最初に「保存した期限が残っているか」を見て、残っていれば何もしません。
Google は、前に出したトークンを使い回して返すことがあります。そのため、受け取った時点で有効期間の一部がもう過ぎていて、アプリが記録した 50 分より先に、Google 側で期限が切れることがあります。
その状態になると、Firestore は 401 を返すのに、アプリは「期限はまだ残っている」と判断して取り直しません。やり直しもまた 401 になり、「Cloud の権限がありません」が出ます。simple も JS も、エクスプローラーもインポート/エクスポートも、同じ作りなので同じように失敗します。

直し方（提案）

Firestore から 401 が返ったら、保存してあるトークンを消すようにします（FirestoreClient の requestText で、401 の時に消す）。
そうすれば、取り直しの処理が新しいトークンを取りに行きます。普段は画面を出さずに取れます。
FirestoreClient を使っている 3 つのモジュール（Query・Explorer・Transfer）全部に効きます。

D. query モードの JS（再変更）
================================================================================

ドキュメント一覧で「query」を選ぶ。編集欄のコードを、各項目のコードに置き換えて「Run」。
Run のたびに「書き込みの確認」「JS を実行します。書き込みがある場合があります」が出る →「実行」。

D1. where を複数（違うフィールド）
　以前は、where を 2 つ書いても最後の 1 つしか効かなかった。
　where を 1 つだけにした時と件数（「ヒット n」）を比べ、全部の条件が効いていることを見る。

D1-1. 2 つ
async function run() {
  return db.collection('companyQ')
    .where('city', '==', 'Sapporo')
    .where('active', '==', false)
    .get();
}
　【端末】city が Sapporo で、かつ active が false のものだけが出る（seed_co_0007 を含む）。
　　　　　where('city', ...) だけの時、where('active', ...) だけの時より、件数が少ない（または同じ）。

  →　OK





D1-2. 3 つ
async function run() {
  return db.collection('companyQ')
    .where('city', '==', 'Sapporo')
    .where('active', '==', false)
    .where('name', '==', 'Panda Mint Studio')
    .get();
}
　【端末】3 つ全部に当てはまるものだけが出る。

  →　OK





D1-3. 等しい ＋ 範囲（複合インデックスが要る組み合わせ）
async function run() {
  return db.collection('companyQ')
    .where('city', '==', 'Sapporo')
    .where('employees', '>=', 1000)
    .get();
}
　【端末】インデックスがあれば、city が Sapporo で employees が 1000 以上のものが出る。
　　　　　無ければ「実行できませんでした」と、Firestore のメッセージ（インデックスを作るリンク付き）が出る。

→　修正済　リンク不要に変更







D1-4. 同じフィールドの範囲 ＋ orderBy ＋ limit
async function run() {
  return db.collection('companyQ')

  →　OK

D5. 書き込み
async function run() {
  const {FieldValue} = admin.firestore;
  const ref = db.collection('companyQ').doc('t_js');
  await ref.set({n: 1, arr: ['a'], keep: 'k', parent: db.doc('companyQ/seed_co_0007')});
  await ref.set({m: 2}, {merge: true});
  await ref.update({n: FieldValue.increment(5), arr: FieldValue.arrayUnion('b'), at: FieldValue.serverTimestamp()});
  await ref.update({keep: FieldValue.delete()});

  return [await ref.get(), await added.get()];
}
　【端末】2 件が出る（t_js と、自動 ID のドキュメント）。自動 ID をメモする（D11 で消す）。

D7. batch
async function run() {
  const b = db.batch();
  for (let i = 0; i < 3; i++) b.set(db.collection('companyQ').doc('t_b' + i), {i});
  b.delete(db.collection('companyQ').doc('t_js'));

}
　【端末】t_b0〜t_b2 が出る。
　【Firestore】t_b0〜t_b2 ができ、t_js が消えている。

D8. transaction
async function run() {
  const ref = db.collection('companyQ').doc('t_b0');
  await db.runTransaction(async t => {
    const snap = await t.get(ref);
    t.update(ref, {i: snap.data().i + 100});
  });
  return ref.get();
}
　【Firestore】t_b0 の i が 100 になる。
　t.update の行と t.get の行を入れ替えると、「transaction の読みは、書きより前に行ってください」が出る。

  →　OK
