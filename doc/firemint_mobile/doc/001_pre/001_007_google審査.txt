================================================================================
これは何か
================================================================================

  審査:
    Google の人が FireMint を見て、
    「人の Google アカウントを触ってよいアプリだ」と認める手続き。

  通すと:
    実機に出る「このアプリは Google で確認されていません」が消える。
    使う人数の上限（未審査だと生涯 100 人）も外れる。

  通さなくても:
    自分で詳細から進めて、コレクションは見られる。
    一般公開するなら足りない。このアプリは一般公開する。だから審査する。


  審査ではないもの（もう済んでいる）:
    Audience を In production にしたこと（Publish app）。
    あれは「許可画面を出す」ための公開。審査待ちではなかった。


================================================================================
二つのプロジェクトを混ぜない
================================================================================

  firemint_m のログイン（審査を出す場所）:
    Google Cloud プロジェクト  firemint-m
    画面  https://console.cloud.google.com/auth/audience?project=firemint-m

  ホームとプライバシーのページ:
    Firebase プロジェクト  firemint-e801f
    ホーム        https://firemint-e801f.web.app/
    プライバシー  https://firemint-e801f.web.app/privacy.html

  使う人が触るデータ:
    名簿に手入力したプロジェクト（例: mintfarm）。審査の提出先ではない。


================================================================================
取る権限（これ以外は足さない）
================================================================================

  サインイン（名前・メール）
  Firestore を読む・書く
    https://www.googleapis.com/auth/datastore

  Cloud 全体、プロジェクト一覧、は取らない。


================================================================================
出す前に揃えるもの
================================================================================

  済んでいる想定:
    Audience が In production
    Branding にアプリ名 FireMint、問い合わせメール
    ホームとプライバシーの URL、許可ドメイン firemint-e801f.web.app
    ロゴはまだ載せない（載せると審査必須になる。出すときに載せる）

  出すときに揃える:
    1  スコープに datastore だけが入っている
    2  プライバシーの文面が、実際にやることに合っている
       （Google で入る。許可した人の、指定した Firestore だけ。広告用に集めない）
    3  実機のデモ動画（下）
    4  スコープを取る理由の文章（下）
    5  ロゴ（任意ではない。審査に出すなら載せる）
       正方形、120px 以上、1MB 以下


================================================================================
デモ動画
================================================================================

  ネットで開ける URL にする（未公開のドライブは避ける）。
  同意画面の左下の言語は English にする。

  映す順:
    1  アプリを開く（FireMint と分かる）
    2  Google でサインインする
    3  許可の画面。datastore / Firestore が見えること
    4  許可する
    5  プロジェクト ID を手入力して名簿に足す（または既存を開く）
    6  コレクション一覧が出る
    7  ドキュメントを開いて見る（書くなら確認ダイアログも）

  アプリ名は Branding の FireMint と一致させる。


================================================================================
スコープの理由（提出欄に書く文のたたき）
================================================================================

  FireMint is a Firestore console. After the user signs in with Google,
  they type a Google Cloud / Firebase project ID they already have access to.
  The app reads and writes Firestore collections and documents in that
  project only, using https://www.googleapis.com/auth/datastore.
  It does not list the user's Google Cloud projects and does not request
  cloud-platform.


================================================================================
出し方
================================================================================

  プロジェクト firemint-m で作業する。mintfarm では出さない。

  1  https://console.cloud.google.com/auth/audience?project=firemint-m
     In production であること。Testing なら先に Publish app。

  2  左の Branding
     ホーム・プライバシー・許可ドメインが上の URL であること。
     ロゴを載せて保存。

  3  左の Data Access / スコープ
     datastore だけ。余分は消す。

  4  Audience または同意画面の「審査の準備 / Prepare for verification」
     内容を確認して進む。

  5  スコープの理由を貼る。動画の URL を貼る。

  6  Submit for verification
     これが出すボタン。Publish app とは別。

  返事は、プロジェクトのオーナー／編集者のメールに来る。
  carepanda886@gmail.com が届くこと。


================================================================================
出したあと
================================================================================

  通るまで:
    自分と使う人は、赤い注意の「詳細」から進める。
    「安全なページに戻る」はキャンセル。

  通ったら:
    赤い注意は出なくなる。

  差戻しが来たら:
    動画が短い、プライバシーが薄い、権限が広い、が多い。
    datastore 以外を足していないか先に見る。
