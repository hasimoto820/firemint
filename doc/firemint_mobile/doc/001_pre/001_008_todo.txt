1. 保存で型が壊れる(重大)

起きること

ドキュメント詳細を開く(createdAt がタイムスタンプ型のドキュメントとします)
何も編集せずに「保存」を押す
createdAt が文字列型に変わって保存される

原因

FirestoreClient.kt の読み込み(unwrap)が、型の情報を捨てて普通の JSON にしています。保存(wrap)は JSON の見た目から型を推測し直すので、元に戻りません。保存はドキュメント全体の置き換えなので、触っていないフィールドも巻き込まれます。

元の型	保存後
タイムスタンプ	文字列
リファレンス	文字列
バイト列	文字列
位置情報(geoPoint)	マップ(latitude / longitude)
数字だけの文字列("0901234567"、"00123")	整数(先頭の 0 も消える)
小数の 1.0	整数の 1

同じ問題がある操作

ドキュメント一覧の「複製」と「リネーム」も、同じ読み書きを通るので型が壊れます。
「リネーム」は新しい ID で作ってから元を削除するので、元のドキュメントのサブコレクションは引き継がれず、削除済みドキュメントの下に取り残されます。

インポート/エクスポート(公式ダンプ)は型付きのまま扱っているので、この問題はありません。

直す方向

JSON で表せない型だけ、型名付きの形で編集欄に出す案を勧めます(例: {"__type__": "timestamp", "value": "2026-10-12T00:00:00Z"})。編集欄の見た目が変わるので、形式は相談して決めたいです。

    → OK

・　現状のqueryはwhereを１つしか置けない。
    ↓
    モバイルは、Firestore の REST API の runQuery を Kotlin から呼んでいます（FirestoreClient.kt）。この API は、Admin SDK が内部で使っているものと同じ検索の仕組みです。where の複数指定（compositeFilter）、orderBy、limit は、もともと全部使えます。いまのコードも、simple の範囲条件（2 つ目の条件）ですでに compositeFilter を使っています。

    1 つしか効かない本当の原因
    制限の原因は 2 か所にあり、どちらも自前のコードです。

    makeChain が、where を 1 つしか覚えておかない作りになっている
    Kotlin へ渡す引数が field, operator, value 1 組に固定されている

    直し方

    makeChain で where と orderBy を何個でもためておき、条件の一覧（またはそのまま structuredQuery の JSON）として Kotlin に渡します。
    Kotlin はそれを runQuery に投げるだけにします。


    →　決定：query モードの JS（admin SDK と同じ書き方の一部）

    ＊　使えるもの
        db         collection(path) / collectionGroup(id) / doc(path) / batch() / runTransaction(fn)
        検索       where(field, op, value) 何個でも（AND） / orderBy(field, 'asc' | 'desc') / limit(n) / get()
        コレクション  doc(id) / add(data)
        ドキュメント  get() / create(data) / set(data, {merge}) / update(data) / delete() / collection(id) / id / path
        get() の結果
            検索    docs / size / empty / forEach
            1 件    id / ref / exists / data()
        batch       create / set / update / delete / commit()
        transaction get / create / set / update / delete（読みは書きより前）
        admin.firestore
            FieldValue  serverTimestamp() / increment(n) / arrayUnion(...) / arrayRemove(...) / delete()
            Timestamp   now() / fromDate(d) / fromMillis(ms) / toDate() / toMillis()
            GeoPoint    new GeoPoint(latitude, longitude)

    ＊　limit
        書いた値をそのままサーバーに渡す。書かなければ件数制限なし。

    ＊　部分一致・存在する・存在しない
        他の条件はサーバーで絞り、取ってきた結果を端末でさらに絞る。
        limit で取ってきた件数が limit に達した時は、一部しか見ていないので partial の表示を出す。

    ＊　演算子
        not-in / array-contains-any を足す（simple と JS の両方）。

    ＊　値の型
        書く値: 整数 → 整数、それ以外の数 → 小数。Date / Timestamp → 日時。GeoPoint → 位置情報。
                DocumentReference → リファレンス。__firemint_type の形も書ける（編集欄と同じ）。
        data(): __firemint_type の形で返す（編集欄と同じ）。

    ＊　run() の戻り値
        検索の結果 / 1 件の結果 / それらの配列 → 一覧に出す。
        何も返さない → 0 件。

    ＊　実行
        read-only のプロジェクトでは実行しない。実行前に確認を出す。


    →　対応

    ＊　JS（src/features/query/native/js_db.ts）
        db / admin を作る。where・orderBy・limit は条件をためるだけで、get() で Kotlin に渡す。
        条件は「検索の条件の一覧（filters / orderBy / limit）」の JSON にして渡す。
        書き込みは、書く内容の一覧（writes）にして渡す。
            set           ドキュメント全体の置き換え
            set + merge   書いたフィールドだけ（updateMask）
            update        キーのフィールドだけ（updateMask）。ドキュメントが有る時だけ
            create / add  ドキュメントが無い時だけ。add の ID は 20 文字の自動 ID
            FieldValue    書く内容とは別に、updateTransforms として渡す
                          delete() は、updateMask に入れて値を渡さない
        値は、編集欄と同じ形（普通の JSON ＋ __firemint_type）にして渡す。
        Kotlin の呼び出しごとに、権限が切れていたら取り直して、その呼び出しだけをやり直す。
        runTransaction は、ABORTED の時に fn からやり直す（5 回まで）。失敗した時は rollback する。
        run() の実行と、戻り値を一覧にするのは query.ts の runJsQuery。

    ＊　Kotlin（FirestoreClient.kt / QueryModule.kt）
        jsQuery             条件の一覧から structuredQuery を組み立てて runQuery。
                            where が 2 つ以上なら compositeFilter（AND）。
                            == null / != null と NaN は unaryFilter にする。
                            部分一致・存在する・存在しないは、結果を端末で絞る。
        jsGet               1 件読む。無い時は null
        jsCommit            writes を commit で 1 回で書く（全部成功か、全部失敗）
        jsBeginTransaction  transaction を始める
        jsRollback          transaction を取り消す
        transaction 中の読みは、runQuery / GET に transaction を付ける。
        フィールドのパスは、英数字と _ 以外を含む名前を ` で囲む。

    ＊　演算子（query.ts / FirestoreClient.kt）
        not-in（NOT_IN）/ array-contains-any（ARRAY_CONTAINS_ANY）を足した。simple でも , 区切りの一覧。

    ＊　表示
        partial の時は「limit の N 件の中だけを絞り込みました」を出す（QueryHeader.tsx）。























・　権限（アクセストークン）が切れたまま、取り直さない

    アプリはトークンを受け取った時から 50 分を期限として保存するが、Google が使い回しのトークンを
    返すと、それより先に Google 側で期限が切れる。Firestore は 401 を返すが、取り直しの処理

    →　対応

        次の取り直しで、新しいトークンを取りに行く。
        FirestoreClient（Query・Explorer・Transfer）と、Auth ユーザーの IdentityToolkitClient・ServiceUsageClient。
