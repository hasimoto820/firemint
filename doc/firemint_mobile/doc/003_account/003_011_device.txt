
device

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@

端末（device）を、独立したコレクションにする。トライアルの起点は、端末が持つ。




================================================================================
骨格
================================================================================

　account … 契約。課金を管理する
　user    … 使っている人（匿名を含む）
　device  … 実機。インストールの絶対の指標

accounts/{accountId}
    └─ members/{uid}             ← その契約に入っている Google アカウント
users/{uid}
    └─ devices/{deviceIdHash}    ← この人が使っている端末の一覧
devices/{deviceIdHash}           ← 端末。firstUseDate を持つ

・1台の端末を、複数の user が使うことがある（匿名 → A → B）。
・「誰か」は Firebase Auth（匿名の間は端末ごと、Googleログイン後は Google アカウントごと）。
　「どの実機か」は devices。




================================================================================
不変条件（迷ったらここに戻る）
================================================================================

　1　firstUseDate を持つのは、devices だけ。一度決まったら変わらない。
　2　利用できるのは、次のどちらかが成り立つ時だけ。
　　　・契約中　　　　　　　　… account 単位。subscriptions から都度計算する
　　　・この端末のトライアル中 … 今 < この端末の firstUseDate + 60日
　3　トライアルは、端末ごと。同じ Google アカウントでも、端末ごとに残り日数が違う。
　4　devices を読み書きできるのは、サーバー（Cloud Functions）だけ。
　5　devices に入れるのは、日付だけ。端末のIDは、ハッシュ（SHA-256）にしてドキュメントIDに使う。
　6　users/{uid}/devices は、「誰がどの端末で使っているか」の記録。使うのは、次の2つ。
　　　・データ削除の時に、端末へ期限（expireAt）を入れるかどうかを決める
　　　・端末を登録する時に、その端末に残っている古い匿名ユーザーを探す
　7　端末に期限（expireAt）を入れるのは、その端末と結び付いている Google アカウントが、
　　　他に1つも無い時だけ。
　8　期限切れの devices は、まだ物理的に残っていても、無いものとして扱う。




================================================================================
データ構造
================================================================================

devices/{deviceIdHash}
    ├─ firstUseDate   ← この端末で最初に使い始めた日時。トライアルの起点
    └─ expireAt       ← データ削除から1年後。ふだんは無い（Firestore の TTL の対象）

users/{uid}
    ├─ email
    ├─ name
    ├─ platform
    └─ accountId

users/{uid}/devices/{deviceIdHash}
    ├─ deviceIdHash   ← ドキュメントIDと同じ値（端末から、全 user の一覧を横断して探すため）
    └─ addedAt        ← この人が、この端末で使い始めた日時

端末の SQLite（cached_user）
    uid / accountId / firstUseDate（この端末の日付の写し）

・deviceIdHash ＝ Android ID の SHA-256。ハッシュにするのはサーバー。




================================================================================
端末を登録する
================================================================================

サーバーの関数（仮称 registerDevice）。アプリが Android ID を渡す。
アプリが呼ぶのは、SQLite に写しが無い時と、Googleログインで uid が切り替わった時（合流）。

　1. devices/{deviceIdHash} が無ければ、firstUseDate = 今 で作る。あれば、日付はそのまま。
　2. expireAt が入っていれば消す。
　3. devices が既にあった場合は、古い匿名ユーザーを掃除する（下の「古い匿名ユーザーの掃除」）。
　4. users/{呼び出した人のuid} が無ければ作る（email / name / platform / accountId = null）。
　5. users/{呼び出した人のuid}/devices/{deviceIdHash} が無ければ作る。
　6. firstUseDate を返す。アプリは、SQLite に写す。

・users/{uid} を作るのは、この関数だけ。email / name の更新は、アプリから直接行う。
・オフラインで登録できなかった時は、SQLite に写しが無いままになる。
　日付が分からない間は、利用不可。次に起動した時に、もう一度登録する。




================================================================================
状態遷移表
================================================================================

| # | 場面                                   | devices（この端末）            | users                      | users/{uid}/devices          |
|---|----------------------------------------|--------------------------------|----------------------------|------------------------------|
| 1 | 初めての起動                           | 作る（firstUseDate = 今）      | 匿名で作る                 | 追加                         |
| 2 | 日常の起動                             | 触らない（SQLite の写しで判定）| そのまま                   | そのまま                     |
| 3 | 再インストールの後の起動               | 日付はそのまま                 | 新しい匿名で作る。古い匿名ユーザーは削除 | 追加（古い匿名の分は削除） |
| 4 | データ削除の後の起動             | 日付はそのまま。expireAt を消す| 新しい匿名で作る           | 追加                         |
| 5 | Googleログイン（昇格。uid は同じ）     | 触らない                       | email / name を更新        | そのまま                     |
| 6 | Googleログイン（合流。uid が切り替わる）| 触らない                      | 匿名の users を削除        | 匿名の分を削除。合流先に追加 |
| 7 | メンバー脱退 / owner に外される        | 触らない                       | accountId をクリア         | そのまま                     |
| 8 | データ削除                       | 「期限を入れる条件」の通り。日付は触らない | 削除           | 全て削除                     |
| 9 | expireAt を過ぎた                      | TTL が削除する                 | —                          | —                            |
| 10| 9 の後の起動                           | 作る（firstUseDate = 今）      | 新しい匿名で作る           | 追加                         |

・1 / 3 / 4 / 10 は、アプリから見ると同じ動き（SQLite に写しが無い → 端末を登録する）。
・8 の直後は、アプリを閉じる。同じ起動のままでは、4 へ進まない（003_012_datadel.txt）。
　すぐに 4 へ進むと、入れたばかりの expireAt が、その場で消えてしまうため。


期限を入れる条件（8 の中身）
　削除する人の一覧にある端末を、1台ずつ見る。
　├─ その端末が、他の Google アカウントの一覧にも入っている → expireAt を入れない
　└─ 他に誰もいない → expireAt = 今 + 1年

　・数えるのは、Googleログイン済みの user だけ。
　・例: A と B が同じ端末を使っている
　　　A がデータ削除 → B がいるので、期限は入らない
　　　その後 B もデータ削除 → 他に誰もいないので、期限が入る


古い匿名ユーザーの掃除（「端末を登録する」の 3 の中身）
　匿名のまま再インストールすると、新しい uid で始まる。前の匿名ユーザーは、誰も入れないまま
　サーバーに残るので、ここで消す。

　全 user の一覧（users/*/devices）から、同じ deviceIdHash のものを探す
　↓
　見つかった user のうち、次の全部に当てはまるものを削除する
　（Firebase Auth のユーザー、users/{uid}、その一覧）
　　・匿名のまま（Google が紐づいていない）
　　・accountId が無い
　　・いま呼び出している本人ではない




================================================================================
利用状態の判定
================================================================================

users/{uid}.accountId を持つ？
├─ YES → その account の最新の subscription が有効 → subscribed → 利用可能
│        （有効でなければ、下のトライアルの判定へ）
└─ NO  → 下へ

この端末の firstUseDate + 60日以内？
├─ YES → trial → 利用可能
└─ NO  → expired → 利用不可

・この端末の firstUseDate は、SQLite の写しを使う。オフラインでも判定できる。
・画面の文言は、「この端末のトライアル 残り○日」。




================================================================================
割り切り（塞がないもの）
================================================================================

・新しい端末に入れるたびに、60日のトライアルが付く。
・端末の初期化・署名鍵の違いで Android ID が変わった時は、新しいトライアルになる。
・devices が消えた後（期限を入れてから1年間、その端末で一度も起動しなかった時）は、
　新しいトライアルになる。
