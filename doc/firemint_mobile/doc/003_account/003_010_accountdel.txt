================================================================================
背景（いま何が起きるか）
================================================================================

・「自分のデータを削除」/「退会」は、users/{uid} と Firebase Auth のユーザーを削除する。
・次の起動は新しい匿名ユーザーになり、recoverUid(deviceId) は候補を見つけられない
　（元の users が消えているため）。
・新しい users/{uid} が firstUseDate = 今 で作られ、トライアルが60日に戻る。
・匿名でも、Googleログイン済みでも、トライアル切れの後でも、アカウント画面から2タップでできる。
・003_001_plan.txt 基本ルール5は、これを「許容する（決定）」としていた。→ この決定を変える。




================================================================================
決定
================================================================================

＊　退会・データ削除の後も、deviceId（Android ID）と firstUseDate だけは保持を続ける。
　　それ以外（email / name / uid / accountId / 購入記録）は、これまで通り削除する。

＊　deviceId は、生のままでは持たない。ハッシュ（SHA-256）にして持つ。
　　照合はハッシュ同士でできる。元の Android ID には戻せない。

＊　保持する場所は、新しいコレクション accountHistory。
　　users/{uid} は残さない（Auth ユーザーを消すと recoverUid の候補にならないため、
　　残しても復元に使えない。「削除したのに users が残る」のは説明もしにくい）。

＊　保持する期間は、退会・データ削除から1年。1年を過ぎたら削除する。
　　1年を過ぎた後に同じ端末で起動した場合は、新しいトライアルが始まる（許容する）。
　　消すのは Firestore の TTL（expireAt を指定。期限後、通常24時間以内に自動で消える）。

＊　owner には「自分のデータを削除」ボタンを出さない。owner は「退会」だけ。
　　（owner が押すと、退会と同じ処理が、メールアドレス入力の二重確認なしで動いていたため）

＊　プライバシーポリシーと削除案内ページを書き換える（「反映先」参照）。
　　Google Play のアカウント削除要件は、不正防止（fraud prevention）のための保持を、
　　ユーザーへ明示することを条件に認めている。




================================================================================
不変条件（迷ったらここに戻る）
================================================================================

　1　トライアルの起点（firstUseDate）は、退会・データ削除ではリセットされない。
　　　リセットされるのは、Android ID が変わった時（端末の初期化・署名鍵の違い）と、
　　　削除から1年が過ぎた時だけ。
　2　accountHistory に入るのは deviceId のハッシュと firstUseDate と、期限を決めるための日時だけ。
　　　個人を直接指す情報（email / name / uid / accountId）は入れない。
　　　生の deviceId も入れない（ドキュメントIDにも、フィールドにも）。
　3　accountHistory を読み書きできるのはサーバー（Cloud Functions）だけ。
　　　アプリからは読めないし、書けない（firestore.rules で全面拒否）。
　4　引き継ぐ firstUseDate は、必ず「より古い方」。新しい日付で上書きしない。
　5　accountHistory は、匿名ユーザーの復元（recoverUid）の代わりではない。
　　　戻るのは firstUseDate だけ。uid・契約・メンバーは戻らない
　　　（Googleユーザーの契約は、これまで通り、退会で消える）。
　6　期限切れの accountHistory は、まだ物理的に残っていても、無いものとして扱う
　　　（TTL は期限ちょうどには消えない。読む側で必ず expireAt を見る）。
　7　ハッシュにするのはサーバー（Cloud Functions）。アプリは、これまで通り生の deviceId を
　　　渡すだけ（ハッシュの方式をアプリに持たせない。方式を変える時に、サーバーだけで済む）。




================================================================================
データ構造
================================================================================

accountHistory/{deviceIdHash}
    ├─ firstUseDate   ← 引き継ぐトライアルの起点（削除された users/{uid}.firstUseDate）
    ├─ deletedAt      ← 退会・データ削除をした日時（サーバー時刻）
    └─ expireAt       ← deletedAt + 1年。これを過ぎたら削除する（Firestore の TTL の対象フィールド）

・ドキュメントIDは deviceIdHash ＝ deviceId（Android ID）の SHA-256（16進の文字列）。
　recoverUid が受け取る deviceId から、サーバーが同じ計算をして引く。
・users/{uid}.deviceId は、これまで通り生の値（匿名ユーザーの復元 recoverUid に使うため。
　users は退会・データ削除で消える）。ハッシュにするのは accountHistory だけ。
・1つの端末につき1件。同じ端末で2回目の削除をした時は、同じドキュメントを更新する
　（firstUseDate は古い方を残す。deletedAt / expireAt は新しい削除の日時にする）。




================================================================================
状態遷移表
================================================================================

■ 書き込み（accountHistory に記録する時）

| 操作                                   | 削除される users     | accountHistory に書く deviceId（ハッシュにして） |
|----------------------------------------|----------------------|---------------------------------------------|
| データ削除（未所属。匿名 / Google）    | 本人                 | 本人の users.deviceId と、操作した端末のID  |
| データ削除（member）                   | 本人                 | 同上                                        |
| 退会（owner）                          | owner本人のみ        | 同上（owner の分だけ）                      |
| 退会（owner）で残される他member        | 削除されない         | 書かない（users が残るので不要）            |
| 合流・復元で捨てる仮の匿名ユーザー     | 仮の匿名             | 書かない（本人の正規の users は別に残る）   |
| メンバー脱退 / owner に外される        | 削除されない         | 書かない                                    |

※「操作した端末のID」も書く理由:
　users/{uid}.deviceId は、その users を最初に作った端末のID。Googleユーザーが2台目の端末で
　削除した場合、2台目のIDは users に入っていない。書かないと、2台目でトライアルが戻る。

■ 読み取り（起動時。users/{uid} がまだ無い仮の匿名ユーザーの時だけ）

| recoverUid の候補      | accountHistory（期限内） | 結果                                                   |
|------------------------|--------------------------|--------------------------------------------------------|
| 見つかった             | 見ない                   | 元の匿名uidに戻る（これまで通り）                      |
| 見つからない           | ある                     | 仮の匿名が本物になる。firstUseDate は履歴の値を引き継ぐ |
| 見つからない           | 無い / 期限切れ          | 仮の匿名が本物になる。firstUseDate = 今（これまで通り） |

※ 引き継いだ後も、accountHistory は消さない（期限まで残す）。
　 もう一度削除された時は、同じ firstUseDate のまま、期限だけが延びる。




================================================================================
フロー
================================================================================

■ 退会・データ削除（003_002_flow.txt「退会・データ削除要請」に足す）

（ownerなら Google Play の解約 → 成功を確認）
↓
削除する本人の users/{uid} から、deviceId と firstUseDate を読む
↓
accountHistory/{deviceIdHash} に書く（本人の users.deviceId と、操作した端末のID を、
それぞれハッシュにする。同じなら1件）
　├─ firstUseDate = 既にあれば古い方、無ければ users の値
　├─ deletedAt    = サーバー時刻
　└─ expireAt     = deletedAt + 1年
↓
これまで通り、users / members / accounts / subscriptions / Auth ユーザーを削除する

※ 順序: accountHistory を先に書いてから、users を削除する。
　 逆にすると、途中で失敗した時に firstUseDate を失う。


■ 起動（003_002_flow.txt「起動時の判定順」③に足す）

③ recoverUid(deviceId)
     ├─ 見つかった → これまで通り
     └─ 見つからない
          ├─ accountHistory/{deviceIdHash} が期限内にある
          │     → サーバーが users/{uid} を作る。firstUseDate = 履歴の値
          │       （アプリは firstUseDate に過去の日付を書けない。rules が作成時刻に限定している）
          └─ 無い / 期限切れ → これまで通り。アプリが users/{uid} を作る。firstUseDate = 今




================================================================================
決めたこと（経緯。未決定は無し）
================================================================================

＊　deviceId を、生のまま持つか、ハッシュ（SHA-256）にして持つか
　　決定: ハッシュ。
　　　　　照合はハッシュ同士でできる。ポリシーにも「元のIDに戻せない形で保持する」と書ける。

＊　1年を過ぎたデータの消し方
　　決定: Firestore の TTL（expireAt を指定。期限後、通常24時間以内に自動で消える）。
　　　　　消えるまでの間は、不変条件6の通り、読む側で expireAt を見て無視する。

＊　コレクション名
　　決定: accountHistory。
　　　　　trialHistory は採らない。トライアル中の人だけでなく、契約を続けていた人が
　　　　　退会・データ削除した場合も対象になるため、trial という名前は中身と合わない。

＊　owner に「自分のデータを削除」ボタンが出ている件（別件だが、同じ画面）
　　owner が押すと、退会と同じ処理が、メールアドレス入力の二重確認なしで動く。
　　決定: owner には出さない（削除案内ページの「owner は退会、member は自分のデータを削除」と合う）。
　　　　　サーバー側（deleteMyData の owner 分岐）は、そのまま残す。画面を通さずに呼ばれた時も、
　　　　　Google Play の解約 → 削除の順序を守るため。
