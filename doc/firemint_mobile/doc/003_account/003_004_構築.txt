方針
================================================================================

•	001_003_ディレクトリ構成.txt の既存方針（feature-based外側、layer-based内側）に合わせる。
•	account は「FireMint操作ユーザー」の識別・契約・課金を扱う独立 feature とする。
	connection（"FireStore操作ユーザー"用、接続先Firestoreへの認証）とは別物。
•	003_003_misc.txt の「Client直接 / Cloud Functions経由」一覧が、
	そのまま functions/ 以下の関数分割に対応する。
•	現状 functions/ ディレクトリ・firestore.rules は未設置。今回新設する。
•	Cloud Functions のリージョンは、Firestore(asia-northeast1 / Tokyo)に合わせて
	asia-northeast1 に統一する（functions/src/index.ts の setGlobalOptions で指定）。

•	仕様レビュー（003_006_todo.txt）が一段落した時点で、実装を丸ごと作り直すべきか検討した。
	結論: 作り直さない。見つかったズレはtodoでパッチする（決定）。
	根拠:
	  ・一番間違えやすい部分（匿名→Google昇格・合流でのcustom token受け渡し、createAccount/
	    joinAccountのトランザクション整合、uid中心の設計、entitlementを保存せず都度計算する
	    構造）は、既に仕様と一致しており、実機でも動作確認済み（003_003_misc.txt「実機テストの
	    確認状況」）。ここを作り直すのは、既に解決済みの細かい罠（Android IDの署名鍵依存、
	    RTDNが検証より先に届く0.2秒のレース、acknowledgeの3日制限など）を踏み直すリスクの
	    方が大きい。
	  ・実際に見つかったズレは局所的な数件（1関数につき数行〜1画面の追加）で、「設計が
	    間違っていた」のではなく「後から決まった仕様に、まだ追従していないだけ」だった。
	  ・共通処理（requireOwnerAccount等）もそのまま使い回せる。将来のチーム化を見越した
	    users/accounts/members/subscriptionsの分離、ownerUid1フィールドでのowner判定という
	    構造自体は、既に「このままでいい」と結論が出ている（チーム化する場合も、直すのは
	    構造ではなくルールの方）。
	見つかった食い違い（配線中の追加発覚も含め計8件）は、003_007_todo_done.txtに記録済み。
	この検討にあたり、auth.ts・billing.ts・deleteAccount系・Android Kotlin側・
	firestore.rulesも確認した。firestore.rulesは仕様どおり（書き込み全面拒否、
	読み取りはmemberのみ）。android/.../AccountModule.kt の validateSession は、
	オフラインと無効の区別を既に実装済みだった（reload()の通信エラーはtrueを返し、
	無効と決めつけない。003_002_flow.txt「起動時の判定順」①の決定と一致。ドキュメントより
	コードの方が先行していた）。

Firestore まわり（新設）
================================================================================

  firestore.rules            … 003_003_misc.txtの一覧を反映
                                 - users/{uid}         : 読み取りは本人のみ。書き込みは【email/nameの
                                                          プロフィール更新】のみ本人可（003_003）。
                                                          email は、IDトークンの email と同じ値に限る。
                                                          作成・削除・accountIdの変更は、Cloud Functions
                                                          （Admin SDK）だけができる
                                                          （registerDevice / createAccount / joinAccount /
                                                          removeMember / deleteAccount / deleteMyData 等）。
                                 - users/{uid}/devices : 読み書き不可（Functionsのみ）
                                 - devices             : 読み書き不可（Functionsのみ）
                                 - accounts/{accountId} : members に自分のuidがあれば read
                                 - accounts/{accountId}/members : 同上、read のみ
                                 - subscriptions        : 所属accountのもののみ read。write は不可（Functionsのみ）
                                 - 上記以外の書き込みは全て deny（Cloud Functions は Admin SDK 経由なのでルールの対象外）

  firestore.indexes.json     … collectionGroup("members") の email フィールドに
                                 collection group スコープのインデックスを追加
                                 collectionGroup("devices") の deviceIdHash フィールドにも同様
                                 （端末から、全 user の一覧を横断して探す）
                                 devices.expireAt の TTL

  firebase.json               … functions ブロックと firestore ブロック（rules/indexesのパス）を追加

Google ログイン / OAuth の構成（重要。混ぜないこと）
================================================================================

プロジェクトは2つ。役割を分ける。

  firemint-m   (750211540930)  … Googleの審査（datastore等のsensitiveスコープ）を通した元締め。
                                 OAuthクライアント（Android用・Web用）はここに置く。
  firemint-e801f (647968484767) … Firebase（Auth / Firestore / Functions / Hosting）。
                                 OAuthクライアントは Web（自動作成）1つだけ。Androidは置かない。

制約（実際にぶつかった）:
  「パッケージ名 + 署名SHA-1」の Android OAuth クライアントは、世界で1つのプロジェクトにしか作れない。
  かつ、Credential Manager の Googleログインは「Androidクライアント」と「使うWebクライアントID」が
  同じプロジェクトに無いと [28444] Developer console is not set up correctly になる。
  → 両機能（connection / account）とも firemint-m の Web クライアントID を使う。

  Androidクライアント（firemint-m に作成済み）:
    FireMint_M     … デバッグ署名
    FireMint upload … 自前リリース署名（SHA-1 F2:5A:BE:A8:...:D2:BD）
    FireMint Play  … Play App Signing（SHA-1 6A:19:B0:1A:...:8B:37）

  Firebase Auth（firemint-e801f）の Google プロバイダに、
  firemint-m の Web クライアントID（750211540930-fovai8js...）を
  「外部プロジェクトのクライアントIDのセーフリスト」として登録する。
  これで、firemint-m のIDで取ったGoogleのIDトークンを Firebase が受け付ける。

  やらないこと:
    firemint-e801f 側に Android OAuth クライアントを作る（自動作成される。
    Firebase に SHA-1 を登録すると作られてしまうので、登録しない。登録済みなら
    Firebase 側のSHA削除 + Cloud Console のクライアント削除が必要）
    審査を firemint-e801f から出す（002_006_002 と同じ方針）

  署名証明書の見つけ方（Play App Signing の SHA-1）:
    Play Console上で探すより、Playストア経由で入れた実機のAPKから取る方が確実。
      adb pull で base.apk を取り出し、
      apksigner verify --print-certs --max-sdk-version 36 <apk>
    （--max-sdk-version 36 は、新しい量子耐性署名ブロックを読めないJDK対策）
