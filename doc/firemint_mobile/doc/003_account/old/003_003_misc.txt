================================================================================
Client直接 / Cloud Functions経由 の切り分け
================================================================================

001_plan / 002_flow で決めたフローを見返すと、既に暗黙的に
「どの操作をクライアント直書きにするか、Cloud Functions経由にするか」が決まっている。
これをFirestore Security Rules設計の前提として一覧化しておく。

基本方針:
•	自分のデータの読み取り、および自分のuid単体の初期作成のみクライアント直接。
•	それ以外の書き込みは実質すべて Cloud Functions 経由。
•	読み取り専用の権限はクライアントに広く許可し、
	検証・整合性・プライバシーが絡む書き込みはサーバー側に寄せる。


| # | 操作                                             | 対象                        | 方式              | 理由                                                              |
|---|--------------------------------------------------|-----------------------------|-------------------|---------------------------------------------------------------------|
| 1 | 初回 users/{uid} 作成                            | 自分のuid                   | Client直接        | 自分のuidへの書き込みのみ。ルールで request.auth.uid == uid を検証できる |
| 2 | users/{uid} 通常読み取り                         | 自分のuid                   | Client直接        | 同上                                                                |
| 3 | Android再インストール時、deviceIdで既存uid検索   | 他人（＝過去の自分）のuid   | Cloud Functions   | 任意のdeviceIdを総当たりで検索されるリスク。custom token発行とセットなのでどのみち必須 |
| 4 | Google認証時、emailで招待歴を照合・合流          | 他accountのmembers          | Cloud Functions   | collectionGroupでの横断検索。他人の所属状況が漏れるとプライバシー問題 |
| 5 | account作成（＋自分をmembersに追加）             | 新規account                 | Cloud Functions   | account本体とmembersの2ドキュメントを整合させて作る必要がある（トランザクション） |
| 6 | 2つ目のアカウント追加（owner操作、email仮登録）  | 他accountの所属チェック含む | Cloud Functions   | 他account横断検索＋owner権限チェックが必要                          |
| 7 | メンバー脱退（owner操作）                        | members削除＋users.accountIdクリア | Cloud Functions | owner権限チェック＋2ドキュメントの整合更新                          |
| 8 | 課金検証・acknowledge・subscriptions作成         | subscriptions                | Cloud Functions   | クライアント申告を信頼できない。購入検証は必須でサーバー側          |
| 9 | RTDN受信によるsubscriptions更新                  | subscriptions                | Cloud Functions   | Googleからのサーバー間通知。クライアントは関与しない                |
| 10| 退会（アカウント削除）                           | account全体                  | Cloud Functions   | Google Play解約との順序制御が必須                                   |
| 11| データ削除要請（member自身）                     | 自分のmembers/usersのみ      | Cloud Functions   | 本人確認・監査ログの観点。影響範囲は自分のみだが経由は統一          |
| 12| accounts/{accountId} 読み取り                    | 自分の所属account            | Client直接        | ルールで「自分のuidがmembersに存在するか」を検証できれば安全        |
| 13| members一覧読み取り                              | 自分の所属accountのみ        | Client直接        | 同上。他accountは読めないようルールで制限                           |
| 14| subscriptions読み取り（利用可否判定用）          | 自分の所属accountのみ        | Client直接        | 読み取り専用。書き込みは全てCloud Functions側で行うので改ざんリスクなし |

先送りにした項目（優先度低）
================================================================================

•	2アカウント上限に達している状態でのエラーUI表現。
•	既に別accountのmemberであるGoogleアカウントを追加しようとした際のエラーUI表現。
•	脱退させられたmemberが過去purchaserだった場合の課金の扱い（個人利用前提のためレアケース）。
•	Stripe（デスクトップ）側の解約操作権限（owner限定か、購入者本人のみか）は、デスクトップ側のドキュメントで決定する。




================================================================================
テスト購入の挙動（ライセンステスター）
================================================================================

•	テスト購入の月額サブスクは、実際の1か月ではなく約5分ごとに自動更新される（最大6回、
	購入から約35分後に期限切れ）。RTDN（SUBSCRIPTION_RENEWED / EXPIRED）と
	expiryTime の更新、期限切れ後の画面表示の確認に使える。
•	更新のたびに androidRtdnWebhook が起動する。成功時は「RTDNを反映しました」
	（通知の種類・accountId・新しい expiryTime）がログに出る。
	（firebase functions:log --only androidRtdnWebhook）
•	検証に失敗してacknowledgeされなかった購入は、Googleが自動で取り消す
	（SUBSCRIPTION_REVOKED / EXPIRED。voidedPurchaseNotification も届く）。
	この時、FireMint側には記録が無いので「未知のpurchaseToken」の警告になるが、正常。
•	購入ダイアログにテスト購入の表示が出ない場合は、ライセンステスターの設定を
	確認してから購入すること（本当に課金される）。




================================================================================
実機テストの確認状況
================================================================================

確認済み:
  ✅ 匿名認証での起動 / Googleログイン / account自動作成
  ✅ 購入 → サーバー検証 → 「契約中」表示
  ✅ 検証失敗後の復元（購入済みでも購入ボタンから先へ進める）
  ✅ RTDN疎通（テスト通知、購入通知、5分ごとの更新通知）
  ✅ 画面を開き直しても契約情報が消えない（accountIdはサーバーを正とする）
  ✅ 自動更新の反映と期限切れ（購入から約35分「契約中」が続き、その後
     「トライアル残り○日 + 購入ボタン」に戻る。expiryTime から都度計算する設計どおり）

  ✅ 2つ目のGoogleアカウントをメンバーに追加 → 別端末でログイン → 同じ契約で「契約中」

未確認:
  ⬜ 解約（Playストアから）→ 期限まで使え、期限後に切れる
  ⬜ 再インストール後の復元（recoverUid / 購入の復元）
  ⬜ 退会（Google Playの自動解約 → Firestoreデータ削除の順序）
  ⬜ データ削除要請（member / 未所属）
