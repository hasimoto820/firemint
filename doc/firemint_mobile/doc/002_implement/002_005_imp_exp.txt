概要
================================================================================


＊　公式ダンプのインポート / エクスポート
　　JSON は 002_007。CSV はやらない。プロジェクト間コピーはやらない。

＊　出先で可能な範囲。机の大きな作業はデスクトップ。
　　怖い作業だと分かったまま、手が届くようにする。

＊　正はファイル。中身を SQLite に吸って正にしない。
　　開いてメモリに載せた中身は、その場限り。


================================================================================
UI
================================================================================


入口はホームの「インポート/エクスポート」だけ。
explorer の既存ページ（コレクション一覧、ドキュメント一覧、詳細）には置かない。
001_006 の「入口はホームとコレクション一覧」は、コレクション一覧を使わない。

最初の画面で、インポートかエクスポートかを選ぶ。
ヘッダーに切替トグルは置かない。選び直すときは戻る。
インポートとエクスポートは次にやることが違う。同じ画面のモードではない。



ホーム → インポート/エクスポート → エクスポート

エクスポートしたいとき:
    → スコープ（プロジェクト / コレクション / コレクショングループ）

  プロジェクト:
    → プロジェクトを選ぶ
    → 出す
    コレクション一覧は出さない。

  コレクション:
    → プロジェクトを選ぶ
    → コレクションを選ぶ
    → 出す

  コレクショングループ:
    → プロジェクトを選ぶ
    → コレクション ID を選ぶ
    → 出す

  形式（公式ダンプ / JSON）は「出す」の画面で選ぶ（002_007 json）。

インポートしたいとき:
  ホーム → インポート/エクスポート → インポート
    → 宛先プロジェクトを選ぶ
    → ファイルを選ぶ（公式ダンプ / JSON）
    → 検証（任意）
    → 書き方（追記 / 上書き）を選ぶ（002_007 json）
    → 実行


================================================================================
詳細
================================================================================


＊　エクスポート
対象はプロジェクト、コレクション、コレクショングループ。スコープはエクスポートに入った直後に選ぶ。
今開いている画面の「これを出す」ではない。TOP から対象を言い直す。

プロジェクト出しの画面に、コレクション一覧を置かない。
一覧が出るのは、スコープがコレクションのときだけ。


＊　インポート
ファイルに従う。コレクションの載せ替えはしない。
書く先の path はダンプが持っている。

ファイルは、エクスポート元のプロジェクトを持っている（エンティティのキー）。
宛先プロジェクトは選ぶ。その中のコレクションはファイルどおり。
元と宛先が違う時は、実行前に確認を出す（002_007 json）。


＊　検証と実行
並びは「検証」「実行」。

検証は書込なし（dry run）。
  ・形式、件数
  ・類似／差異は、ある／ない（コレクションとドキュメント ID）。インポートだけ。
  ・同じ path でフィールドが違う、はこの画面に出さない。

検証は任意。押さなくても実行できる。
大規模だと検証だけで n 時間かかる。見るか進むかはユーザー。

検証なしで実行するときは、書いていない、と警告する。
警告のあと実行可。

read-only:
  検証はできる。実行はできない。


＊　検証結果の画面（インポート）
件数まで。ドキュメント行は出さない。エクスポートでは使わない。

見出しは「クラウド」「ファイル」だけ。
三段（両方 / クラウドだけ / ファイルだけ）にはしない。
独立した二つのリストにもしない。行はコレクション名で揃える。片側に無いときは空欄。

            クラウド         ファイル
Group       280  20赤        310  50赤
Member      9000 200赤       9600 600赤
Post        10500            10500
Inquiry     300（名が赤）     （空）
Company     （空）            400（名が赤）

赤は行の背景（dangerBg）。文字色は変えない。
  コレクションが片方にしかない → その行を赤背景
  両方あるがドキュメント ID が違う／中身が違う → その行を赤背景
  コレクションも同じ → 背景なし

「だけ」の件数は、差の絶対値ではない。クラウドにだけ 20、ファイルにだけ 50、のように側ごとに出す。
詳細検証では、下段に差異のあるドキュメント数も出す。

クラウドにだけあるコレクション／ドキュメントは、実行しても消えない。検証は消さない。


＊　安全
実行は shared/safety の確認を通す。
検証は確認の対象ではない（書かないから）。


================================================================================
ディレクトリ構成
================================================================================


出す・入れるは features/data_transfer。
explorer は知らない。画面の本体を shared/ui に置かない。
進捗（ダンプの裏実行）も data_transfer。


src/
  app/
    HomeScreen.tsx                  … カード「インポート/エクスポート」が入口

  features/
    data_transfer/
      ui/
        TransferScreen.tsx          … ホームから。入れる / 出す → スコープ → 対象
        VerifyTable.tsx             … 検証結果。クラウド / ファイル
      native/
        transfer.ts                 … 出す / 検証 / 入れる（RN → Kotlin）
      shared/
        transfer.ts                 … 型（スコープ、検証行）

    workspace/                      … 宛先プロジェクトの名簿。既存


android/
  data_transfer/                    … 論理の箱。公式ダンプのファイル I/O
  app/src/main/java/com/firemint/
    data_transfer/                  … 読む / 書く / 検証 / 進捗
    shared/
      FirestoreClient.kt            … 既存。初期化はここだけ


公式ダンプは接続ではない。開く・入れるのは data_transfer。
Firestore の実処理は android/。RN からは native の口だけ。

その他
================================================================================


□ zip か、公式フォルダのままか
→　デスクトップに合わせる。zip。


□ 衝突したドキュメント
→　追記ならスキップして進む。上書きならファイルの中身で置き換える（002_007 json）。
　　検証の有無で書き方は変えない。検証は見るためのもの。


□ ファイルの置き場
→　デフォルトはアプリの documents/。その上でユーザー選択可。


□ 類似 / 差異の画面
→　インポートのみ。件数まで。見出しはクラウド / ファイル。行はコレクション名で揃える。
　　赤は名前か件数か、スコープで分ける。本文「検証結果の画面」が正。
