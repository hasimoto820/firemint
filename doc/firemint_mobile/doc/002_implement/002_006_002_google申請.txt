================================================================================
これは何か
================================================================================

  001_007 の datastore 審査とは別に、同じ firemint-m の同意画面に
  identitytoolkit スコープを追加で申請する手続き。

  新しいアプリの審査ではない。同じ OAuth 同意画面に、スコープを 1 つ足して
  再提出する。datastore が通っていることは変わらない（外さない、消さない）。

  identitytoolkit は non-sensitive と確認できた（Data Access 画面で確認済み。
  carepanda886 / firemint-m）。sensitive でも restricted でもない。
  Google の審査ルール上、non-sensitive スコープ単体には「使う理由の文章」も
  「デモ動画」も本来は必須ではない（sensitive / restricted スコープにだけ
  課される要件）。年次のセキュリティ監査も不要。

  ただし datastore が既に sensitive なので、アプリ全体としては引き続き
  審査対象。identitytoolkit を追加した状態で Submit し直す必要があるかは、
  Data Access 画面の「Your app requires verification」表示を見て判断する。

  通すと:
    Auth ユーザー機能を一般公開できる。

  通さなくても:
    datastore 側は今まで通り使える（Auth ユーザーだけが未公開のまま）。

  審査ではないもの:
    001_007 の datastore 分はもう済んでいる。ここで触らない。

取る権限（追加分。datastore は残す）
================================================================================

  Auth ユーザーの一覧・取得・更新・削除
    https://www.googleapis.com/auth/identitytoolkit

  → non-sensitive と確認済み（2026-09-11、Data Access 画面）。
    年次セキュリティ監査は不要。

  対象プロジェクトの Identity Toolkit API 自動有効化
    https://www.googleapis.com/auth/service.management

  → cloud-platform は取らない（002_006_001 で検討し、見送った）。
    代わりに Service Usage API の services.enable が cloud-platform と
    service.management のどちらでも動くことを公式 Discovery Document で確認した
    （serviceusage.googleapis.com の $discovery/rest?version=v1 を直接取得して確認、
    2026-09-11）。service.management は「Google API のサービス設定を管理する」
    専用スコープで、Firestore・Cloud Storage・Compute 等のデータには一切触れない。
    プロジェクトの API 有効/無効の切替以外はできない。
    sensitive/restricted のラベルは Data Access 画面で追加時に要確認。

  Cloud 全体、プロジェクト一覧、は今回も取らない。cloud-platform は取らない
  （やらない、に明記の通り）。

================================================================================
スコープの理由（提出欄に書く文のたたき）
================================================================================

  FireMint also manages Firebase Authentication users of the project the
  signed-in user already administers. Using
  https://www.googleapis.com/auth/identitytoolkit, the app lists, views,
  updates, and deletes end-user accounts (email, display name, phone
  number, password, disabled state, custom claims) of that project only.
  It does not manage the signed-in user's own Google account and does not
  request cloud-platform.

  The app also uses
  https://www.googleapis.com/auth/service.management solely to enable the
  Identity Toolkit API on the project the user specifies, when that API has
  not been enabled yet. It does not read or modify any other API
  configuration and does not access Firestore, Cloud Storage, or any other
  Google Cloud data with this scope.
