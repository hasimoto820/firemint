================================================================================
概要
================================================================================


＊　インポート / エクスポートは、公式ダンプと JSON の 2 つの形式を扱う。

＊　指標は「公式ダンプの仕様に合わせる」。
　　範囲・パス・型・上書きの意味は、公式ダンプと同じにする。

＊　インポートの書き方は「追記」と「上書き」から選ぶ。公式ダンプと JSON で同じ。

＊　値の書き方（__firemint_type 形式）は、次と同じ。
　　・モバイルの編集欄
　　・ドキュメント一覧の query モードの JS（doc.data() の結果、書く値）
　　・デスクトップ版の serialize.ts（diff のレポートの dump / project）

＊　デスクトップ版も、この仕様で作る。


================================================================================
ファイルの形
================================================================================


＊　JSON Lines。zip にしない。
　　拡張子は .jsonl。文字コードは UTF-8。改行は LF。

＊　1 行目は見出し。2 行目からは、1 行に 1 ドキュメント。

＊　見出し

    {"kind":"firemint-docs","version":1,"projectId":"firelock-27739",
     "scope":{"kind":"collection","path":"companyQ","includeSubcollections":false},
     "createdAt":"2026-10-26T01:23:45.678Z"}

    （実際は 1 行で書く）

    kind        "firemint-docs" で固定
    version     1
    projectId   エクスポート元のプロジェクト
    scope       エクスポートの範囲
                  {"kind":"project","roots":["companyQ","users"]}
                  {"kind":"collection","path":"companyQ/doc1/orders","includeSubcollections":false}
                  {"kind":"group","collectionId":"orders"}
    createdAt   作った日時（UTC、ISO 8601）

＊　ドキュメント

    {"path":"companyQ/doc1","data":{"name":"山田","age":30}}

    path    プロジェクトの一番上からのフルパス
    data    フィールド。値は「値の書き方」の形

＊　ファイル名
    公式ダンプと同じ付け方で、拡張子だけ .jsonl にする。
      export-project-{projectId}-{時刻}.jsonl
      export-collection-{コレクションID}-{時刻}.jsonl
      export-group-{コレクションID}-{時刻}.jsonl


================================================================================
値の書き方
================================================================================


＊　JSON でそのまま書ける型は、普通の JSON にする。
    文字列 "abc" / 整数 30 / 小数 1.0 / 真偽値 / null / 配列 / マップ

＊　JSON で書けない型は、__firemint_type で型の名前を添える。

    タイムスタンプ   {"__firemint_type":"timestamp","iso":"2026-10-12T00:00:00Z"}
    位置情報         {"__firemint_type":"geopoint","latitude":35.6,"longitude":139.7}
    リファレンス     {"__firemint_type":"reference","path":"users/abc"}
    バイト列         {"__firemint_type":"bytes","base64":"AAEC"}
    NaN / 無限大     {"__firemint_type":"double","value":"NaN"}
                     （"Infinity" / "-Infinity" も同じ）

＊　読む時に、見た目から型を推測しない。
    "0901234567" は文字列、30 は整数、1.0 は小数。

＊　リファレンスの path は、プロジェクトの一番上からのパス。
    インポート先のプロジェクトのドキュメントを指す。


================================================================================
エクスポート
================================================================================


＊　範囲は公式ダンプと同じ 3 通り。
    プロジェクト            選んだルートコレクション。サブコレクションを含む
    コレクション            パスで指定。サブコレクションを含めるかを選ぶ
    コレクショングループ    コレクション ID で指定

＊　形式（公式ダンプ / JSON）は、出す画面で選ぶ。範囲の選び方は形式で変わらない。

＊　保存先は公式ダンプと同じ。
    選ばない時は Documents/FireMint。選ぶ時は、中身のあるファイルを選ぶと上書きの確認を出す。

＊　1 ページ読むたびにファイルへ書き足す。全体をメモリに載せない。

＊　途中で止まった・中止した・中身が無かった時は、書きかけのファイルを消す。


================================================================================
インポート
================================================================================


＊　流れ
    宛先プロジェクトを選ぶ
    → ファイルを選ぶ（.zip と .jsonl のどちらも選べる）
    → 形式は中身で決める（zip なら公式ダンプ、1 行目が firemint-docs の見出しなら JSON）
    → 検証（任意）
    → 書き方（追記 / 上書き）を選ぶ
    → 実行

＊　書き方

    追記（最初に選ばれている方）
      クラウドに無いドキュメントだけを作る。
      既にあるドキュメントには触れない。飛ばした件数として数える。

    上書き（公式ダンプのインポートと同じ）
      ファイルにあるドキュメントは、ファイルの中身で丸ごと置き換える。
      クラウドに無ければ作る。
      ファイルに無いドキュメントには触れない。

    例
      クラウド  companyQ/doc1 = {name:"山田", age:30, memo:"x"}
                companyQ/doc9 = {name:"佐藤"}
      ファイル  companyQ/doc1 = {name:"山田", age:31}

      追記の後  doc1 = {name:"山田", age:30, memo:"x"}   doc9 = {name:"佐藤"}
      上書きの後 doc1 = {name:"山田", age:31}            doc9 = {name:"佐藤"}

＊　実行前の確認文
    追記    「{name} の、クラウドに無いドキュメントだけを作ります。既にあるドキュメントには触れません。」
    上書き  「{name} にあるドキュメントは、ファイルの中身で丸ごと置き換わります。
              クラウドにだけあるフィールドは消えます。ファイルに無いドキュメントには触れません。
              途中で止めても、書いた分は戻りません。」

＊　別のプロジェクトのファイル
    ファイルのエクスポート元と、宛先プロジェクトが違う時は、実行前に確認を 1 回出す。
      JSON         見出しの projectId
      公式ダンプ   エンティティのキーにあるプロジェクト
    確認文「このファイルは {元} からエクスポートしたものです。{宛先} に入れますか？」

＊　リファレンスは、宛先プロジェクトのドキュメントを指すように書く（公式ダンプ・JSON とも）。
    公式ダンプのリファレンスは、エクスポート元のプロジェクト名を持っている。
    インポートの時に、そのプロジェクトを宛先プロジェクトに書き換える
    （Datastore モードの公式インポートと同じ。キーと、キーを参照するプロパティを宛先のプロジェクトにする）。
    検証も、書き換えた後の値でクラウドと比べる。

＊　検証は公式ダンプと同じ。
    簡易（コレクションごとの件数）と詳細（ファイルにだけある / クラウドにだけある件数）。

＊　1 回目に件数を数え、2 回目に書く。全体をメモリに載せない。
    件数を数える時に、見出しが無い・kind や version が違う・中身が無い時は、書き始める前に止める。

＊　読めない行は、書けなかった件数として数え、次の行へ進む。

＊　同じパスが 2 回以上出てきた時は、最初の行だけを書く。
　　2 回目以降は書かずに、飛ばした件数として数える（追記・上書きとも）。

＊　途中で止まった・中止した時、それまでに書いたドキュメントは戻らない。
　　上書きで置き換えた分は、置き換わったまま残る。

＊　結果は公式ダンプと同じ形で出す。
    書いた件数 / 飛ばした件数 / 書けなかった件数 / 途中で止まった理由


================================================================================
実装の順番（モバイル）
================================================================================


段階ごとに実機で確かめてから、次の段階に進む。


＊　1. 公式ダンプのインポートに、追記 / 上書きを足す

    ・インポートの画面で、書き方（追記 / 上書き）を選ぶ。最初は追記
    ・書き方ごとの確認文
    ・ダンプのエクスポート元と宛先が違う時の確認

    確かめること
      追記    既にあるドキュメントが変わらない。無いドキュメントだけができる
      上書き  既にあるドキュメントが、ファイルの中身とまったく同じになる
              （クラウドにだけあるフィールドが消える）。ファイルに無いドキュメントは残る
      別のプロジェクトのダンプを入れる時に、確認が出る


＊　2. JSON のエクスポート

    ・「出す」の画面で、形式（公式ダンプ / JSON）を選ぶ
    ・1 行目に見出し、2 行目から 1 行 1 ドキュメント
    ・範囲は公式ダンプと同じ 3 通り

    確かめること
      テキストエディタで開いて、見出しとドキュメントが読める
      __firemint_type の型（タイムスタンプ、位置情報、リファレンス、バイト列）が正しく出る
      同じ範囲の公式ダンプと、件数が同じ


＊　3. JSON のインポート

    ・.zip と .jsonl のどちらも選べる。形式は中身で決める
    ・見出しが無い・kind や version が違う・中身が無い時は、書き始める前に止める
    ・追記 / 上書き、確認文、別のプロジェクトの確認は、公式ダンプと同じ
    ・読めない行は書けなかった件数。同じパスの 2 回目以降は飛ばした件数

    確かめること
      2 でエクスポートしたファイルを、空のプロジェクトに入れて、型ごと元どおりになる
      手で直した行（値の変更、行の追加）が、そのとおりに入る
      壊した行・同じパスの行が、件数どおりに数えられる


＊　4. JSON の検証

    ・簡易（コレクションごとの件数）と詳細（ファイルにだけある / クラウドにだけある件数）
    ・表示は公式ダンプの検証と同じ

    確かめること
      公式ダンプの検証と、同じ範囲で同じ件数になる


================================================================================
デスクトップ版
================================================================================


＊　serialize.ts に、NaN / 無限大の書き方（__firemint_type: "double"）を足す。

＊　JSON（.jsonl）のインポート / エクスポートと、追記 / 上書きの選択を、この仕様で作る。

＊　追記は、まとめて書き、既にあるもので断られたものを飛ばした件数として数える。
    1 件ずつ、あるかを確かめない。
