1. FireMint へのログイン（Firebase Auth）
モバイルは、初回起動のときに匿名で始めて、あとで Google に昇格するか、既存の uid に合流します。デスクトップも同じ流れにするかを決めます。

Electron には Android の Google ログインの仕組みが無いので、Google ログインのやり方も決める必要があります。今の Firestore 用のログインと同じく、ブラウザでログインして戻ってくる形が考えられます。

→　モバイルと同じ。初めて起動した時に匿名ユーザーを作り、あとで Google に昇格するか、既存の uid に合流する。
　　基本ルール 0〜6（003_001_plan）をそのまま使う。
　　Google ログインは、ブラウザでログインしてアプリに戻る形。




2. deviceId（トライアルの起点）
Android ID の代わりになる値を何にするかを決めます。

→　Windows の MachineGuid を使う（関数に渡す時の名前は deviceId）。




自分で作った番号をファイルに保存する場合：そのファイルを消せば、トライアルをやり直せます。
PC の固有の番号（Windows の MachineGuid など）を使う場合：再インストールしても同じ値です。

モバイルの「再インストールしてもトライアルは続く」に合わせるかどうかが分かれ目です。

→　モバイルと同じ。トライアルは端末ごと。
　　サーバーには、ハッシュ（SHA-256）にして devices のドキュメントID として持つ。生の値は保存しない。




3. 端末に置くキャッシュ
モバイルの SQLite（uid / accountId / この端末の firstUseDate）に当たるものを、どこに置くかを決めます。

→
C:\Users\<ユーザー名>\AppData\Roaming\FireMint\
プロジェクトの一覧（workspaces.json）や Google の OAuth の設定　これらも移動。




4. Stripe の購入の流れと、Webhook をどこで受けるか
Webhook を受ける関数は、モバイルと同じ Firebase プロジェクト（firemint-e801f）の Cloud Functions に置くことになります。
注意点として、デスクトップのリポジトリから関数をデプロイすると、モバイルのリポジトリの関数が消されるおそれがあります。
それを避ける方法（Firebase の「codebase」の分け方）を決める必要があります。

→　
codebase を windows にして、モバイル（android）と分ける。モバイル側は変えない。
関数の名前の頭に windows_ を付ける。
モバイル側の変更が必要になるなら、変更はモバイル側で行う。
デスクトップ側の作業で作成、変更が許されるのは、　windows_ のみ。

6. 解約と、データ削除のときの Stripe 解約

8. トライアルの起点（firstUseDate）をどこに置くか

→　モバイルと同じ。firestore:devices/{MachineGuid のハッシュ}.firstUseDate
　　Google ログインすると、課金の状態（account）を引き継ぐ。課金が切れたら、その PC の firstUseDate で判定する。
　　データ削除では、devices に期限（expireAt）を入れるだけで消さない。トライアルはリセットされない。





9. 割り切り

→　MachineGuid の書き換え・Windows の入れ直し・別の PC では、トライアルを使い直せる。対策しない。
　　（モバイルの「端末の初期化」と同じ扱い）
　　PC の中身を丸ごと複製して配った場合などに、別の PC で MachineGuid が同じになり、トライアルを共有することがある。対策しない。



10. FireMint へのログインに使う OAuth クライアント：Firestore 用のログインとは別に、どのクライアントで Firebase Auth にログインするかです。
モバイルでは、firemint-m の Web クライアントを使っています。

→　firemint-m にデスクトップ用のクライアントを1つ作り、Firebase のセーフリストに登録する。
　　FireMint へのログインと Firestore 用のログイン（11）は、このクライアントを共用する。




11. Google の認証の期限が1週間
デスクトップが使っている OAuth クライアントは、firemint-m でも firemint-e801f でもない、別のプロジェクト（番号 415032174806）のものです。
そのプロジェクトがまだ「テスト中」の状態だと、Google の決まりで、ログインの有効期限が7日になります。おそらくこれが原因です。

直すには、審査を通した firemint-m にデスクトップ用のクライアントを作り、そちらに移ります。
その場合、権限の範囲（デスクトップは cloud-platform、モバイルの審査は datastore）の整理も要ります。

→　Firestore 用のログインも、10 で作るクライアントを使う。
　　権限はモバイルと同じ（datastore / identitytoolkit / service.management）。cloud-platform は使わない。
　　プロジェクトの一覧は取得しない。モバイルと同じく、projectId を入力して繋ぐ。
