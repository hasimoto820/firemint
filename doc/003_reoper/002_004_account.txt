デスクトップ版のアカウント・課金の決定事項と、Stripe の設定。
流れ（解約・データ削除を含む）は 002_005_flow.txt、Stripe の通知の書き方は 002_006_webhook.txt。




================================================================================
決定事項
================================================================================


1. FireMint へのログイン（Firebase Auth）
　モバイルと同じ。初めて起動した時に匿名ユーザーを作り、あとで Google に昇格するか、既存の uid に合流する。
　基本ルール 0〜6（003_001_plan）をそのまま使う。
　Google ログインは、ブラウザでログインしてアプリに戻る形。
　Firebase Auth は裏側（main）で動かす。画面側（renderer）にログイン情報を渡さない。
　Firebase Auth の Web API を直接呼ぶ。refresh token は safeStorage で暗号化して保存する。
　関数の呼び出しと、契約の読み取りも裏側で行う。


2. deviceId（トライアルの起点）
　Windows の MachineGuid を使う（関数に渡す時の名前は deviceId）。
　トライアルは端末ごと。再インストールしても同じ値なので、トライアルは続く。
　サーバーには、ハッシュ（SHA-256）にして devices のドキュメントID として持つ。生の値は保存しない。


3. トライアルの起点（firstUseDate）
　モバイルと同じ。devices/{MachineGuid のハッシュ}.firstUseDate
　Google ログインすると、課金の状態（account）を引き継ぐ。課金が切れたら、その PC の firstUseDate で判定する。
　データ削除では、devices に期限（expireAt）を入れるだけで消さない。トライアルはリセットされない。


4. 割り切り
　MachineGuid の書き換え・Windows の入れ直し・別の PC では、トライアルを使い直せる。対策しない。
　（モバイルの「端末の初期化」と同じ扱い）
　PC の中身を丸ごと複製して配った場合などに、別の PC で MachineGuid が同じになり、トライアルを共有することがある。対策しない。


5. users/{uid}.platform
　"windows"


6. Cloud Functions
　サーバー側（Functions・Firestore ルール・Hosting）は、すべて firemint_m で変更し、デプロイする。
　デスクトップ用の関数は firemint_m/functions/ にあり、名前の頭に windows_ を付ける（codebase は default）。
　モバイルの関数（discardAnonymous / joinAccount / createAccount など）は、デスクトップからもそのまま呼ぶ。
　このリポジトリの hosting/ と functions/ は使わない。


7. subscriptions/{ID} の ID
　Stripe の subscription の ID（sub_…）。


8. 解約とデータ削除
　どちらもアプリの中で行う。流れは 002_005_flow.txt「解約」「データ削除」。


9. 再ログインしても、つないでいるプロジェクトの認証が古いまま
　再ログインで繋ぎ直す。


10. OAuth クライアント
　firemint-m のデスクトップ用クライアント（Firebase のセーフリストに登録）。
　FireMint へのログインと Firestore 用のログインで共用する。
　権限は datastore / identitytoolkit（と openid / email）。
　プロジェクトの一覧は取得しない。モバイルと同じく、projectId を入力して繋ぐ。
