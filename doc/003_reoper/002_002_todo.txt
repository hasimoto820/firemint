＊　data_transfer（インポート / エクスポート）
    仕様は 002_007 json。モバイル版と同じ動きにする。

    ・JSON（.jsonl）のインポート / エクスポート
    ・インポートの書き方の選択（追記 / 上書き）。最初は追記
    ・追記の書き方
        まとめて書き、既にあるもので断られたもの（ALREADY_EXISTS）を、飛ばした件数として数える。
        1 件ずつ get() で、あるかを確かめない。
        （確かめてから書くまでの間に同じドキュメントができると、バッチがまるごと失敗するため）
    ・リファレンスは、宛先プロジェクトのドキュメントを指すように書く（公式ダンプ・JSON とも）。
        公式ダンプのリファレンスはエクスポート元のプロジェクト名を持っているので、
        インポートの時に宛先プロジェクトに書き換える。検証も、書き換えた後の値で比べる。
    ・serialize.ts に、NaN / 無限大の書き方（__firemint_type: "double"）を足す。
    ・エクスポートで、null のフィールドを落とさない。
        document_to_entity.ts の encodeValue が null の時に null を返し、
        encodeProperty がそれを「書かない」と扱うので、null のフィールドがダンプから消える。
        null は、中身の無い値（field 5 が空）として書く。
        読む側（entity_to_document.ts）が、空の値を null に戻すかを合わせて確かめる。

    → OK

＊　account（アカウント・課金）
    ・deviceId
        Android 版の deviceId（Android ID）に相当する値を、デスクトップ版で独自に作る。
        端末を見分けるための値で、本人確認には使わない。（003_001）
    ・users/{uid}.platform は "windows"。（003_001）
    ・課金は Stripe。Stripe 関連のコードは、デスクトップ側のリポジトリに置く。（003_004）
    ・購入の流れ（003_002「デスクトップで課金」）
        購入できるのは、Google ログイン済みの owner だけ。
        購入が終わったら subscriptions/{ID} を作る（provider = "Stripe"）。
        ID の決め方は、デスクトップ側で決める。
        subscriptions のドキュメントの形は、Android と同じ（003_001）。
    ・データ削除の時は、Stripe 側の解約も同じ流れで行う。（003_002）

    ・googleの認証方法（現在は、期限が一週間）

    ・Google に再ログインしても、すでにつないでいるプロジェクトは古い認証のまま（アプリの再起動で直る）
