================================================================================
方針
================================================================================

  デスクトップのサブスクは、アプリが Stripe を直接叩かない。

    desktop（Google Auth の uid）
        ←→  Firebase Functions（firemint-e801f）
            ←→  Stripe

  購入も、継続確認も、Stripe に触るのは Functions だけ。
  Stripe の秘密鍵は Functions に置く。Electron には入れない。

  アプリは起動時に一度だけ Functions へ聞く。
  Functions は Stripe を毎回叩かず、サーバが持っている expiredDate で判定する。

  connection の Google（対象 Firestore へ繋ぐ）とは別。
  課金用 Google は Firebase Auth（プロジェクト firemint-e801f）。
  FireMint にログインする Google と、管理対象プロジェクトの Google は同じでも別でもよい。


================================================================================
登場するもの
================================================================================

  1. デスクトップ
       Firebase Auth（Google）で FireMint にログイン
       起動時に Functions へ id token を渡す
       返ってきた expiredDate で開閉する

  2. Firebase Auth + Firestore（firemint-e801f）
       ユーザー（uid）
       課金レコード（expiredDate など）

  3. Cloud Functions
       Checkout セッションを作る（購入開始）
       Stripe webhook で expiredDate を更新する
       起動確認: token を検証し、expiredDate を返す（このとき Stripe は見ない）

  4. Stripe
       Customer / Subscription / Checkout / Customer Portal
       Price: 日本 ¥500、海外 $5

  5. hosting/
       紹介・DL。購入ボタンはアプリ内 or LP から Functions の Checkout へ


================================================================================
データ（サーバ）
================================================================================

  Firestore（firemint-e801f、アプリの管理対象 DB ではない）:

    users/{uid}
      email
      stripeCustomerId
      status          … trial / active / past_due / canceled
      expiredDate     … この日時まで使える（Functions が書く）
      trialEnd        … トライアル終了（初回ログインで決めてよい）

  expiredDate の更新は webhook が行う。
    invoice.paid / checkout.session.completed
      → current_period_end を expiredDate に書く
    customer.subscription.deleted / 支払い失敗の確定
      → expiredDate を今、または猶予の終わりにする

  アプリ起動の確認 API は Stripe を呼ばない。
  読むのは Firestore の expiredDate だけ。


================================================================================
ユーザーの流れ
================================================================================

  購入
    1. アプリで Google ログイン（Firebase Auth）
    2. 未加入なら「購入」（日本 / 海外）
    3. Functions が Checkout を作る（client_reference_id / metadata に uid）
    4. ブラウザで払う
    5. Stripe webhook → Functions が users/{uid}.expiredDate を更新
    6. 次回起動（または購入直後の再確認）で active

  毎回の起動
    1. 保存してある Google セッションで id token
    2. Functions に token を渡す（起動時のみ）
    3. Functions: token → uid → expiredDate
    4. 今 < expiredDate なら active。過ぎていれば locked
    5. 端末に expiredDate をキャッシュ（オフライン用）

  解約・カード変更
    Functions が Customer Portal の URL を返す。
    アプリはブラウザで開く。結果は webhook が expiredDate に反映。


--------------------------------------------------------------------------------
トライアル（60日）
--------------------------------------------------------------------------------

  サーバの users/{uid}.trialEnd で持つ（端末だけに持たない）。
  初回 Google ログイン時に Functions が trialEnd = now + 60日 を書く。
  起動確認は expiredDate と trialEnd の遅い方まで可、でよい。
  Stripe trial とは二重にしない。


--------------------------------------------------------------------------------
オフライン
--------------------------------------------------------------------------------

  起動時に Functions へ届かない:
    端末キャッシュの expiredDate まで使える。
    キャッシュも期限切れなら locked。
  無限オフラインにはしない。


================================================================================
アプリが持つ状態（端末）
================================================================================

  Firebase Auth のセッション（refresh）
  最後に受け取った expiredDate
  最後に確認できた時刻

  状態:
    trial / active / locked
    （起動できないときだけ、キャッシュ期限までの grace）


--------------------------------------------------------------------------------
何を閉じるか（locked）
--------------------------------------------------------------------------------

  接続・閲覧・クエリは触れる。
  書く系を閉じる:
    ドキュメント更新・削除
    一括操作
    インポート / 転送
    Auth ユーザーの変更

  購入・ポータルへの導線を出す。


================================================================================
Functions の口（仕様）
================================================================================

  起動確認
    入力: Firebase id token
    処理: 検証 → uid → Firestore
    出力: status, expiredDate
    Stripe は呼ばない

  購入開始
    入力: id token, price（jp / us）
    処理: Customer が無ければ作る → Checkout Session
    出力: Checkout URL（アプリがブラウザで開く）

  ポータル
    入力: id token
    出力: Customer Portal URL

  webhook
    Stripe → Functions
    users/{uid} の expiredDate / status を更新
    署名検証する


================================================================================
features/auth
================================================================================

  main
    Google ログイン（FireMint 用 Firebase Auth）
    起動時にだけ確認 API
    expiredDate のキャッシュ
    locked なら書く系 IPC を拒否

  renderer
    ログイン
    状態表示
    購入 / ポータル（ブラウザ）

  Stripe SDK はアプリに入れない。


================================================================================
やらないこと（最初）
================================================================================

  - ライセンスキーの手貼り
  - アプリ内でカード番号を取る
  - Stripe secret をアプリに置く
  - 起動以外の定期ポーリング（24時間ごと、書く直前の再問合せ）
  - メール＋パスワードの独自会員
  - チーム席・端末1台縛り
  - 年払い・コンビニ


================================================================================
セキュリティ（最低限）
================================================================================

  アプリは改ざんされる前提。
  効くのは Functions が expiredDate を権威として返すこと。
  webhook の署名、id token の検証は必須。
  管理対象の Firestore（ユーザーのプロジェクト）と、
  firemint-e801f のユーザー台帳は混ぜない。

  2. Stripe Price 2本、webhook → expiredDate
  3. 起動確認 API
  4. features/auth（ログイン、起動時確認、locked）
  5. 購入開始 API + Checkout
  6. LP の CTA
