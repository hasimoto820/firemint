--------------------------------------------------------------------------------

1. Simple とツリーが先頭 200 件で止まる
listDocuments が limit(200)。本番のコレクションはそこで見切れる。Query に逃げる前提ならまだしも、左ツリーも同じ 200 なので、奥のドキュメントに辿れない。ページする／もっと読む、は閲覧の芯。

→　そもそも、simple内の値変更の入り口変更。
ヘッダー内のフィールド一括に"値の変更"を設置。ここに移動。


2. メインパネルのドキュメントの、チェックボックスの役割
例えば、複数ドキュメントの削除とか。
今は、選択と、チェックの役割が、少しあやふやになってる。


3. Query の結果を、1 件として直せない
Query は「万能な場所」というスタンスなのに、結果の JSON は readOnly で保存が空。チェック一括の値更新・削除はできる。拾った 1 件を Simple と同じように直す、が無い。スタンスと実装が一番食い違っているところ。

4. Reference を辿れない
型としては path を持っている。クリックしてそのドキュメントを開く、が無い。users/{uid} を参照するデータでは、毎日欲しくなる。

5. 新規でドキュメント ID を書けない
中は documentId を受け取れる。画面の新規は自動 ID の空 {} だけ。Auth の uid を ID にする、は Firestore では普通。

6. Collection Group の入口が無い
Query の db なら書ける。種になるスニペット（collectionGroup("order")）が無いだけ。Query ありきなら、新機能より「よく使う型を置いておく」方が芯に近い。

--------------------------------------------------------------------------------
何をするものか
--------------------------------------------------------------------------------

  Firebase Local Emulator Suite の Firestore に、FireMint から繋ぐ。
  行き先はクラウドではなく、手元で動いているプロセス（例: 127.0.0.1:8080）。

  ユーザーから見ると、接続の 3 本目。

    JSON      サービスアカウントの鍵ファイル → クラウドのプロジェクト
    Google    アカウントでサインイン     → クラウドのプロジェクト
    Emulator  ホスト（HOST:PORT）        → 手元の Firestore Emulator

  左の名簿には、いまの Google / JSON と同じ「プロジェクト 1 行」として並ぶ。
  中身だけ違う。鍵も refresh token もない。覚えておくのはホストと、
  Emulator 側の projectId。


--------------------------------------------------------------------------------
何のためか
--------------------------------------------------------------------------------

  本番を汚さずに、見る・直す・一括・Query・Imp/Exp を試す。
  公式コンソールでは Emulator に繋がない。FireMint / FireFoo 側の仕事。

  つながったあと、その行は他の接続と同じ箱で扱える。
    explorer / query / bulk_operations / data_transfer / auth_users
  「Emulator 専用の閲覧画面」は作らない。閲覧は既存の箱。
  独自ページは、操作 1〜4 を辿るため。

  ただし Auth Emulator は 17-a の対象外（001_020_014）。
  Firestore がつながれば 17-a の Done。Auth ユーザー管理が Emulator で
  動くかは別件。

--------------------------------------------------------------------------------
JSON / Google との違い（芯）
--------------------------------------------------------------------------------

  JSON / Google
    認証がある。クラウドの projectId は鍵または Google のプロジェクト一覧から決まる。
    接続プールのキー = その projectId。

  Emulator
    認証は実質ない。Admin SDK はダミー資格でも受け付ける。
    必要なのは:
      1. ホスト（どこで Emulator が待っているか）
      2. projectId（Emulator はこれでデータを分ける。起動時の名前）

  ここが一番の落とし穴。
    本番 mintfarm-b62db と、同じ id で立てた Emulator を同時に名簿へ載せると、
    いまの接続プールは projectId がキーなので衝突する。
    「同じ名前の手元」と「同じ名前の本番」は、WorkspaceEntry.id を分ける。
    決定を見よ。


--------------------------------------------------------------------------------
箱（001_003 / 001_051 のあと）
--------------------------------------------------------------------------------

  emulator（src/features/emulator）
    独自ページ。File → 接続 → エミュレーターで接続… から開く。
    次へで操作 1〜4 を辿る。1 と 2 は同じ画面。3 と 4 は繋がったあとの分かれ。

  connection
    ホストで繋ぐ実行。connect_entry.ts の 3 本目。
    ホスト文字列を読む。workspace は読まない。
    JSON / Google の接続 UI はここ。Emulator の独自ページは emulator。

  workspace
    名簿と load / unload。
    load のとき connection に「この行を繋げ」と頼む。
    行に持つのは「Emulator である」「ホスト」「表示用の id / label」。
    token も JSON ファイルも持たない。

  shared/firestore
    渡された先でプールに載せる。preferRest は維持（001_004）。
    Emulator 向けの初期化（host / FIRESTORE_EMULATOR_HOST 相当）もここ。
    admin.firestore() 直叩きはしない。client.ts のみ。

今のコード（17-a に入る前）
--------------------------------------------------------------------------------

  WorkspaceAuthType     serviceAccount | google     まだ二値
  workspaces.json 読み  google 以外 → serviceAccount に落とす
  UI 表示               google 以外 → 「json」

  接続プール            Map<projectId, 接続>。3 本目を足すと id 衝突が表面化する

  JSON / Google の繋ぎ方は 001_051 で connection に戻した。
  その上に Emulator を足す、が 17-a の実装。


--------------------------------------------------------------------------------
17-a でやること / やらないこと
--------------------------------------------------------------------------------

  やる
    ■ 接続方式に Emulator がある
    ■ File → 接続 → エミュレーターで接続… から独自ページを開く
    ■ HOST:PORT を指定して Firestore Emulator に繋がる
    ■ 名簿に載る。load / unload / 起動復元が JSON / Google と同じ経路
    ■ 繋がった先で、既存の閲覧・Query・一括が動く（専用の閲覧画面は作らない）
    ■ 本番と区別できる（環境ラベル。誤って本番だと思わない）

  やらない（この見出しの外）
    □ Discover（起動中 Emulator の自動検出）… 17-a には含めない。後で足す
    □ プロジェクト間転送（17-b）
    □ Emulator 同期・公式 emulator export 形式（17-c）
    □ Auth Emulator / Storage Emulator
    □ 一括操作の diff プレビュー（001_050 の 6。保留）

決定（17-a）
--------------------------------------------------------------------------------

    ■ 接続 UI の置き場
       ヘッダー → File → 接続の下に「エミュレーターで接続…」
       独自ページ。次へで操作 1〜4 を辿る。
       1 と 2 は同じ画面（起動確認 + ホスト）。
       3 と 4 は繋がったあとの分かれ（空なら入れる、入っていれば見る）。

    ■ 箱
       src/features/emulator … 独自ページ
       connection            … ホストで繋ぐ実行
       workspace             … 名簿
       shared/firestore      … プール

    ■ WorkspaceEntry.id
       独立した行。Google / JSON の id と被らない値にする。
        { "id": "mintfarm-b62db",          "authType": "google" }
        { "id": "mintfarm-b62db_emulator", "authType": "emulator" }

    ■ Discover
       17-a には含めない。手動 HOST:PORT のみ。後で足す。

    ■ read-only の初期値
       writable（readOnly: false）

    ■ 入れる入力
       JSON。CSV はこのページに含めない。
       コレクション path は聞かない。JSON 丸ごと。
       各ドキュメントの path のまま書く。1 本だけ入れるのは、繋がったあと
       既存の File → インポート → コレクション。

ユーザー操作（概要）
--------------------------------------------------------------------------------

  ・コレクションは FireMint が持たない。書き込み先は Emulator。
  ・FireMint は通路。FireMint で入れるなら、先に繋がっている。
　・firemint以外で接続したemulator内のプロジェクトは操作不可。この先一切考慮に入れない。
　・エミュレーター内にプロジェクト保持している == workspaceに保持している
　　　エミュレーターは、左ツリーの登録解除を無くす



　＊対象ファイル
　　・コレクションjson
　　・projectId付きzip



　＊ユーザー動作（全パターン共通）
　  0. 開発者（または製品の利用者）が、Firestore Emulator プロセスを起動している。
  　   FireMint アプリは、このプロセスを起動しない。
    　 このリポジトリで試すときは、開発者が npm run emulators を実行する。



　＊ユースケース
pattern 1.
　＊ケース
　　・エミュレーター接続
　　・エミュレーター起動のみ / 初回
　
　＊ユーザー動作
　  1. firemintヘッダーからエミュレーター接続

　  2. エミュレーター画面で
    　 127.0.0.1:8080 を選択

　  3. 次画面で
    　 json選択

以上で、エミュレーターにプロジェクト取込、firemintで接続


pattern 2.
　＊ケース
　　・エミュレーター接続
　　・エミュレーター内にプロジェクト保持している / workspaceに保持している
　　・左ツリーにエミュレーター無（切断処理された状態）
　
　＊ユーザー動作
　  1. firemintヘッダーからエミュレーター接続
    　 
　  2. エミュレーター画面で
    　 127.0.0.1:8080 を選択
    　 リストから、projectIdを選択

エミュレーターには既にプロジェクトが入っていた状態。
今回で、firemintがエミュレーター内のプロジェクトを表示

　＊ケース

　　・左ツリーに何らかのプロジェクトが表示されている状態。対象はその、エミュレーター
　
　＊ユーザー動作
　  1. firemintヘッダーから"エミュレーターに追加"
    　 
　  2. エミュレーター画面で
    　 zip選択


以上で、システムは、
・左のツリーに表示
・workspaceに書き込み
上記を行う。

　＊ケース

　　・指定したjsonがコレクションのケース
　　・左ツリーに何らかのプロジェクトが表示されている状態。対象はその、エミュレーター
　
　＊ユーザー動作
　  1. firemintヘッダーから"エミュレーターに追加"
    　 
　  2. エミュレーター画面で
