--------------------------------------------------------------------------------
概要
--------------------------------------------------------------------------------


何をするものか

  キーボードは、画面の大きな塊（エリア）へ着地し、着地したあとは
  その中の項目を辿る。書く・消す・複製はキーに載せない。


何のためか

  Firestore の CRUD は怖い。Del でドキュメント削除、Ctrl+N で新規は、
  フォーカスの食い違いで本番を壊しやすい。確認があってもキーにはしない。

  新規・保存・複製・削除は、今どおりボタンとヘッダーメニューだけ。

  公式より手早く直す、の「手早く」は、エリアへ飛ぶこと。
  塊の中の破壊操作ではない。


芯（決定）

  1. CRUD はショートカットではない
  2. 大きく移動が基本。エリアへ着地する
  3. 着地後は Tab で項目移動。Tab はエリア内に限る
  4. エリアを変えるのは Ctrl+着地 と Ctrl+Tab だけ
  5. 箱は増やさない（001_051）
  6. キーのカスタム割り当ては今回やらない


二段

  Ctrl+* / Ctrl+Tab / Alt     エリア（またはヘッダーメニュー）を変える
  Tab / Shift+Tab             今いるエリアの中だけ。端まで行ったら一周

  ブラウザ既定の「画面全体を Tab で辿る」はやめる。
  左のコレクションにいるとき Tab しても、右の JSON へは行かない。


エリア（画面の塊。001_004 と同じ）

  左ツリー
    プロジェクトエリア      PROJECTS の名簿
    コレクションエリア      FIRESTORE のツリー
    authエリア             AUTH

  右ペイン
    ページタブ              コレクション名 / Imp/Exp などのタブ帯
    設定エリア              モードタブ（Simple / Query）+ 列設定・フィルタ・ページャ
    結果エリア              テーブル + ドキュメント JSON（一つの塊）

  設定エリアは、ショートカット上の帯。
  モードタブとヘッダー（列設定・フィルタ・ページャ）を分けて着地しない。
  結果エリアの表 ↔ JSON は、着地後の Tab で辿る。専用の着地キーは付けない。


今（実装前）

  メニューに CRUD のキー表示がある（Ctrl+N / Ctrl+S / Del）。効いていない。
  今回、表示ごと外す。キーにもしない。

  実際に効いている:
    Ctrl+P     Command Palette
    Ctrl+W     ページタブを閉じる
    Escape     メニュー / Palette / コンテキストを閉じる（部品）

  エリア着地・エリア内 Tab 閉じは、まだ無い。

  Electron の Application Menu accelerator は使っていない。
  カスタムメニューバー（shared/shell）。
  globalShortcut（OS 全域）は使わない。


残してよいキー（CRUD ではない）

  Ctrl+P / ⌘P     Command Palette。名前で飛ぶ。エリア移動の例外
  Ctrl+W / ⌘W     ページタブを閉じる。枠の操作


今回やらない

  ・キーのカスタム割り当て
  ・Settings 内のショートカット一覧画面
  ・OS 全域の globalShortcut
  ・Electron ネイティブ Menu への載せ替え
  ・Command Palette の項目追加
  ・CRUD（新規・保存・複製・削除）のキー
  ・コレクション / サブコレクション / フィールド一括 のキー
  ・Imp/Exp / Transport / Diff / 接続 のキー
  ・ページタブ同士を Ctrl+Tab で切替えること（Ctrl+Tab はエリア巡回）
  ・ヘッダーメニューを Tab の閉路に入れること


Mac

  着地キーの修飾は Cmd（metaKey）。表示は ⌘T など。
  Windows / Linux は Ctrl。コードは ctrlKey || metaKey。
  Alt はヘッダーメニュー（Windows）。Mac のメニューは ⌘ の慣例に合わせ、
  実装時にヘッダーへフォーカスできればよい。


--------------------------------------------------------------------------------
ショートカット一覧
--------------------------------------------------------------------------------


着地（エリアを変える）

  ヘッダーメニュー                 Alt
    メニュー内は矢印。Tab の閉路には入れない

  左ツリー　プロジェクトエリア     Ctrl+T / ⌘T
  左ツリー　コレクションエリア     Ctrl+G / ⌘G
  左ツリー　AUTHエリア            Ctrl+B / ⌘B

  右ペイン　ページタブ             Ctrl+1, 2 / ⌘1, 2
    viewが１ページの際は、Ctrl+1, 2は同じ働き。
    split view、ページが分かれている際は、　
      左ページ                     Ctrl+1 / ⌘1
      右ページ                     Ctrl+2 / ⌘2
  右ペイン　設定エリア             Ctrl+H / ⌘H
    H = ヘッダー帯（モードタブ + 列設定・フィルタ・ページャ）
  右ペイン　結果エリア             Ctrl+N / ⌘N
    新規ドキュメントには使わない。メニューの Ctrl+N 表示は外す



エリア間移動

  次のエリア                       Ctrl+Tab / ⌘Tab
  （逆は Shift+Ctrl+Tab）

  順（画面どおり。端で戻る）:
    プロジェクト
    → コレクション
    → AUTH
    → ページタブ
    → 設定エリア
    → 結果エリア
    → プロジェクト

  ページタブの左右切替ではない。
  ページタブに着地したあと、タブ同士はエリア内の Tab（または左右キー）。


着地後（エリア内）

  次の項目                         Tab
  前の項目                         Shift+Tab

  エリア内に限る。他エリアへ出ない。
  端まで行ったら一周する（端で止めない）。

  例:
    プロジェクトエリア     名簿の各プロジェクト行
    コレクションエリア     ツリーのノード
    ページタブ             開いている各ページタブ
    設定エリア             Simple / Query → 列設定 → フィルタ → ページャ
    結果エリア             テーブル → ドキュメント JSON（とその中のコントロール）

  項目に乗ったあとの CRUD は、クリックまたは画面上のボタン。キーでは発火しない。


例外（閉路を別にする）

  ダイアログ / Palette / 確認
    開いている間はその中だけ。本体のエリアには戻さない

  入力部品が Tab を先に食べる場合
    Autocomplete の確定など。今どおり。エリア移動ではない

  Escape
    Overlay を閉じる。一覧には載せない


枠（CRUD ではない。今の動作を維持）

  Command Palette                  Ctrl+P / ⌘P
  ページタブを閉じる               Ctrl+W / ⌘W
  終了                             メニュー（Win は Alt+F4 が OS で閉じることがある）




ページタブ
  Tab / Shift+Tab で、タブ移動
  split viewの際も、左右のsplitをtabボタンで越える。







ブラウザ / IDE との食い違い（割り切り）

  Ctrl+T     ブラウザの新規タブ → ここではプロジェクトエリア
  Ctrl+N     新規 → ここでは結果エリア。CRUD には使わない
  Ctrl+Tab   ページタブ巡回 → ここではエリア巡回。ページタブは Ctrl+1/2 のあと Tab
  Ctrl+B     太字 / サイドバー → ここではAUTH
  Ctrl+G     次を検索 → ここではコレクションエリア（データツリーへ）
  Ctrl+H     履歴 / 置換 → ここでは設定エリア（ヘッダー帯）

  アプリ内では preventDefault する。ウィンドウフォーカス時のみ。


無効のとき

  そのエリアが無い（未接続、タブゼロ、AUTH 空など）なら、着地キーは何もしない。
  Ctrl+Tab は、存在するエリアだけを辿ってよい。


--------------------------------------------------------------------------------
ディレクトリ構成
--------------------------------------------------------------------------------


方針（001_003 / 001_004 / 001_051）

  箱は増やさない。features/shortcut は作らない。
  定義の正は shared/settings。実行の受け口は shared/shell。
  エリアのフォーカス閉じも shell（画面の枠）。feature にキー受信を散らさない。
  ページは作らない（Settings に割当 UI を足さない）。
  ハイフン禁止。ファイル名は snake_case。


置くもの

  src/shared/settings/shared/
    shortcuts.ts               着地キー・Ctrl+Tab・Palette / 閉じる の定義の正

  src/shared/shell/
    shortcut_dispatcher.ts     window keydown の1箇所（着地・エリア巡回・Palette / 閉じる）
    area_focus.ts              今いるエリア。着地。エリア内 Tab の閉路
    build_app_menus.ts         CRUD の shortcut 文字列を外す。残す表示は定義から読む
    AppMenuBar.tsx             Alt でメニューへ。キー受信の本体は dispatcher

  消す（寄せる）
    FirestorePage.tsx の Ctrl+P / Ctrl+W 直書き → dispatcher
    メニューの Ctrl+N / Ctrl+S / Del 表示


置かない

  src/features/shortcut/
  src/shared/settings/renderer にショートカット画面
  src/main の globalShortcut
  settings.json へのキー割り当て永続化（今回）


責務

  shared/settings/shared/shortcuts.ts
    「この着地 / 枠操作は、このキー」。React も IPC も知らない。

  shared/shell/area_focus.ts
    エリアの境界。Tab をエリア内で一周。Ctrl+着地でその先頭項目へ。

  shared/shell/shortcut_dispatcher.ts
    keydown を1回だけ見る。preventDefault。
    ダイアログ / Palette が開いているときは本体の着地を食べない。

  features/*
    新規のキー受信を足さない。CRUD は今のボタン / メニューのまま。


001_003 との対応

  shared/settings     キー定義（テーマと同じ箱）
  shared/shell        メニュー枠・エリア枠・キー受信
  preload             触らない（キーは renderer の window）


実装の順（案）

  1. エリアを名前どおりに区切る（フォーカスの境界）
  2. shortcuts.ts に着地キーと Ctrl+Tab を定義する
  3. 着地キーでエリア先頭へ。Ctrl+Tab で巡回
  4. エリア内 Tab / Shift+Tab を一周にする
  5. Alt でヘッダーメニュー
  6. Ctrl+P / Ctrl+W を dispatcher へ移す
  7. メニューから CRUD のキー表示を外す
