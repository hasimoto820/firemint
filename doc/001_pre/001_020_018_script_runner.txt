================================================================================
一言で
================================================================================

  差は件数ではない。入力の種類。

  Simple   … コレクションタブの中。画面で見る・直す
  Query    … 同じコレクションタブの中。JS を書いて Run
  Imp/Exp  … コレクションタブと同じ段。ファイルの Import / Export


================================================================================
UI（決定）
================================================================================

  段が2つある。Imp/Exp は下（Simple / Query）ではなく、上（コレクションタブ列）。

    上:  [ equipment ]  [ company ]  [ Imp/Exp ]
    下:  （コレクションタブの中だけ）  [ Simple ]  [ Query ]

  Simple / Query は今のまま、開いているコレクション専用。
  Imp/Exp はコレクションに紐づかない。プロジェクト全体の Import / Export もここに置く。


  Query（現状のまま）:
    コードは画面上の JS。Run したらこの画面で待つ。
    件数では裏に移さない。


  Imp/Exp（今回追加）:
    コードではなくファイル指定。
    Import / Export の設定・実行・進捗を、この1画面でやる。


  ヘッダー File メニュー:

    インポート
      プロジェクト/コレクション
    エクスポート
      プロジェクト
      コレクション

    押したら上段の Imp/Exp タブを開く（無ければ作る）。トグルの初期値を合わせる。
    Import はファイルが先（対象はファイルで決まる）。
    Export は範囲が先（プロジェクト / コレクション）。

    例: エクスポート → コレクション  →  Imp/Exp タブ + Export + Collection


  ヘッダーに Tasks… は置かない。
  進捗は Imp/Exp タブ自身。equipment など別タブに切り替えても処理は続く。
  処理中は上段の Imp/Exp タブを赤くする。


================================================================================
プロジェクト / コレクションは同じ Imp/Exp 画面でよいか
================================================================================

  よい。画面を分けない。

  同じ Imp/Exp タブの上で選ぶ:

    向き:  Import | Export
    対象:  Collection | Project

  Collection のとき:
    初期値は、直前に見ていたコレクションタブ（またはツリー選択）。
    ユーザーが変更できる。
    エクスポート → コレクション で候補が無いとき:
      Imp/Exp タブを開いて、ユーザーにコレクションを選ばせる。

  Import の JSON の行き先:
    初期値は直前のコレクション。ユーザーが変更できる。

  Project のとき:
    接続中プロジェクト全体（zip 等）。path は不要。

  ファイルの種類（JSON / zip）は、向き×対象で決まる。ユーザーに4画面は出さない。


================================================================================
500 件制限は Query に入れるべきか
================================================================================

  入れない。

  500 は Firestore の「1 バッチ書き込み」上限。
  UI のタブ分け基準でも、Query の結果件数上限でもない。

  Query で一括 write する人は、JS の中で batch を 500 件ずつ切る（今どおりコードの話）。
  Imp/Exp の Import / Export も件数で切らない。


================================================================================
Query と Imp/Exp の切り分け
================================================================================

  Query（features/query/ … 済）:
    - async function run()
    - 結果をテーブルに出す
    - この画面で待つ

  Imp/Exp（Phase 13 … 未）:
    - ファイルの Import / Export
    - 進捗はこのタブ
    - 裏で走らせて、コレクションタブ（Simple / Query）に戻れる

  features/script_runner/ は「裏で走らせるエンジン」。
  ユーザーが見る箱は Imp/Exp タブ。Query を太らせない。


================================================================================
なぜ保留か
================================================================================

  - Query と Phase 11 の同期 Import / Export で日常は足りる
  - Imp/Exp タブ＋裏実行は工数が大きい
  - 今すぐ必須ではない

未策定だったもの（決定）
================================================================================

  処理中の表示:
    上段の Imp/Exp タブを赤くする。

  失敗時:
    Firestore に途中まで書いた分は残る（ロールバックできない）。
    ログは Imp/Exp タブの画面下部に出す（どこが失敗したか）。
    Simple / Query やグローバル帯には出さない。

  左ツリー右クリック:
    現状 Export は無い（リネーム / コレクション / フィールド一括）。
    Imp/Exp タブ用に今から載せる必要はない。入口はヘッダー File メニュー。

  同時実行:
    Imp/Exp タブはウィンドウに1つ。
    仕事も1本まで。2つ目は始められない（待つキューも無し）。

  タブの ×:
    コレクションタブを閉じても Imp/Exp の処理は続く（紐づかない）。
    Imp/Exp タブを × したときは、処理中なら確認してから止める。
    コレクションタブを選んでいるだけの非表示中も、Imp/Exp の処理は続く。
