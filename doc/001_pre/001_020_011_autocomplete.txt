================================================================================
目的
================================================================================

  - 入力中に、プロジェクト内の候補（コレクション path / フィールド名）を出す
  - VS Code 的な補完体験の軽量版（エディタ差し替えはしない）
  - 候補の所有を一箇所に閉じ込め、他 feature は呼び出しに徹する
  - 後続 AI が迷わないよう、作成経路と使用経路を厳格に分ける


================================================================================
名前の統一
================================================================================

  - 用語・フォルダ・型はすべて autocomplete に統一する
  - suggestion / SuggestInput / suggestions カタログ名は使わない
  - UI 部品名も AutocompleteInput とする


================================================================================
候補の対象（スコープ）
================================================================================

  含める:
    - collection path（ルートおよびサブコレクション path）
    - フィールド名（ドキュメント本体のキー。ネストは当面トップレベル中心で可）

  含めない:
    - ドキュメント ID
    - createTime / updateTime などのメタデータ名（必要なら後で検討）


================================================================================
UX（軽量補完）
================================================================================

  - 単語単位の補完（いま入力中の単語に対して候補を出す）
  - 入力で候補を絞り込む
  - ↑↓ で候補移動（初期は先頭をハイライト）
  - Enter / Tab で確定
  - Esc で閉じる
  - クリックでも確定可

  レベル:
    - 採用: A 軽量（textarea / input 上で、単語単位の候補 UI）
    - 非採用（今は）: Monaco / CodeMirror への差し替え、構文位置解析つき本格補完


================================================================================
使用場所（候補を出すところ）
================================================================================

  Phase 11.6 の最初（必須）:
    - Query エディタで単語単位の補完を実現する

  広げてよい（後から）:
    - Simple の JSON 編集 ✅
    - テーブルフィルタの field ✅
    - フィールド一括の旧フィールド名 等 ✅
    - 同じ AutocompleteInput / 同じプールを他ページにも入れていく

  ドキュメント ID 入力補完は対象外


================================================================================
アーキテクチャ方針（封じ込め）
================================================================================

  核心:
    - 候補データ（プール）の所有者は features/autocomplete/ のみ
    - 他 feature は「作成 API を呼ぶ」「使用 API を呼ぶ」だけ
    - 各画面が独自プールを持つ案は採らない（ロジック拡散・後続 AI 迷走の元）
    - shared にグローバル台帳 Context を置く案も採らない（有機結合の入口）

  features/autocomplete/ を作る理由:
    - query 専用ではない（JSON・フィルタ・一括フィールド名などでも効く）
    - 「候補の作成・保持・検索」はユーザー機能の塊として独立させられる
    - 入口を一本化すれば、絡みは制御できる（勝手書き込みを禁止）

  shared に置くもの:
    - AutocompleteInput だけ（見た目・キーボード操作の汎用 UI）
    - 候補の状態・永続・ライフサイクルは shared に置かない


================================================================================
責務分担
================================================================================

  features/autocomplete/
    - 候補プールの保持（projectId 単位を推奨）
    - 作成 API（path / field の登録。重複排除）
    - 使用 API（query 文字列 → 候補一覧）
    - 必要なら永続化（当面メモリのみでも可。永続するならこの feature 内）

  shared/ui/AutocompleteInput.tsx
    - 入力 UI と候補リスト表示・キー操作のみ
    - 候補配列は props で受け取る（自分でプールを持たない）

  他 feature（explorer / query / data_transfer / bulk_operations 等）
    - 作成時: autocomplete の作成 API を呼ぶだけ（プール直書き禁止）
    - 使用時: 極力「候補取得 → AutocompleteInput に渡す」に徹する
    - 使用側は 100% 純呼び出しにならなくてもよい（ベストエフォート）
      ※ 作成側の門番は厳守する


================================================================================
作成タイミング（候補を増やすとき）
================================================================================

  path:
    - 接続後〜ツリー表示・展開で path が見えたとき
    - コレクション／サブコレクション作成時（見えた path を登録）
    - リネーム後（推奨: 旧 path を外して新 path を入れる）
    - import で path が増えたとき

  field（スキーマレスなので「読んだ／まとめて分かった」ときにマージ）:
    ○ コレクションを開いてドキュメント一覧を読んだとき（まとめて1回）
    ○ Query Run の結果を読んだとき（まとめて1回）
    ○ 単発の保存（JSON 保存）… その1件のキーだけ add してよい
    ○ import / 一括操作の完了後 … 触ったコレクションを再読込、または結果のキーをまとめて add
    × 大量 insert / import / 一括操作の「各行」では呼ばない（チェックも add もしない）

  field の中の存在チェック:
    - 「無ければ入れる」は addFieldNames 内部（autocomplete 側）で行う
    - 書き込みホットパスから行ごとに autocomplete API を呼ばない

  禁止:
    - features/autocomplete/ 以外が、独自の候補配列を「正」として育てること
    - UI コンポーネントが勝手に Firestore を読んでプールを肥やすこと（作成は明示 API）
    - 大量系の各ドキュメント処理のたびに作成 API を呼ぶこと


================================================================================
ディレクトリ構成（予定）
================================================================================

  src/
    features/
      autocomplete/
        shared/
          types.ts                 … AutocompleteKind, AutocompleteItem 等
        renderer/
          catalog.ts               … プール操作（追加・削除・絞り込み）
          AutocompleteProvider.tsx … feature 内の保持（アプリ全体 shared Context にしない）
          hooks.ts                 … useAutocompleteCatalog / useAutocompleteQuery 等
        main/                      … 当面不要なら空箱 or 作らない（永続が要るまで）
    shared/
      ui/
        AutocompleteInput.tsx      … 汎用入力 UI

  既存の寄せ:
    shared/ui/FieldNameSuggestInput.tsx → AutocompleteInput に置換済み（削除）


================================================================================
モジュール API（アプリ内の呼び出し口。HTTP / IPC ではない）
================================================================================

  作成（他 feature → autocomplete）:
    addCollectionPaths(projectId, paths: string[]): void
    addFieldNames(projectId, fieldNames: string[]): void
    removeCollectionPaths(projectId, paths: string[]): void   … リネーム時など

  使用（他 feature → autocomplete）:
    query(projectId, text: string, kinds?: AutocompleteKind[]): AutocompleteItem[]

  UI:
    <AutocompleteInput
      value={...}
      onChange={...}
      items={...}          … 候補は props。プールは持たない
      ...
    />

  ※ 最終シグネチャは実装時に types.ts で固定。門番は「作成はこの呼び出し口のみ」を崩さない。
  ※ 新規の Electron IPC は増やさない（候補登録は renderer 内の関数呼び出し）。
