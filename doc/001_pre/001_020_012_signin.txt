================================================================================
目的
================================================================================

  - サービスアカウント JSON 以外に、Google アカウントで Firebase に接続できる
  - 権限のある Google アカウントで、そのまま対象プロジェクトを FireMint で扱える
  - 既存の Admin SDK 経路（shared/firestore）はそのまま使い、接続入口だけ増やす
  - UI で接続方式（JSON / Google）を選べる


================================================================================
前提
================================================================================

  - 使う Google アカウントは、対象 Firebase プロジェクトの権限を持っている
  - FireMint は今どおり main 側で Admin SDK を使う（renderer は生トークンに触らない）
  - Emulator 接続は Phase 17（本ドキュメントの対象外）


================================================================================
方針
================================================================================

  今:
    サービスアカウント JSON → admin.credential.cert → Firestore

  Phase 12 で追加:
    Google OAuth（refresh_token）→ admin credential → 同じ getFirestore(projectId)

  つまり接続の入口を 2 系統にする。
  explorer / query / bulk / data_transfer の操作本体は変えない。


================================================================================
責務分担
================================================================================

  features/connection/
    - 接続方式の選択 UI（JSON / Google）
    - Google サインイン開始（IPC → main）
    - サインイン後のプロジェクト一覧表示・選択
    - 既存の JSON ファイル選択フローは維持

  shared/firestore/
    - connectFromServiceAccount（既存）
    - connectFromGoogle({ projectId, refreshToken, ... }) を追加
    - 接続プール Map<projectId, ConnectionEntry> は共通
    - getFirestore(projectId) 以降は今と同じ

  features/workspace/
    - WorkspaceEntry に接続種別を持つ（json / google）
    - Google 接続の再ロードに必要な参照を永続化（トークン本体の扱い方針は下記）
    - load / unload / focused の orchestration は既存どおり

  renderer
    - OAuth の Client Secret / refresh_token / access_token を持たない
    - すべて IPC 経由


================================================================================
OAuth（デスクトップ）
================================================================================

  準備（Google Cloud）:
    - OAuth クライアント種別: デスクトップアプリ
    - Client ID / Client Secret は main 側のみが知る

  スコープ（最低限）:
    - openid
    - email
    - https://www.googleapis.com/auth/cloud-platform

  フロー:
    1. UI「Google で接続」
    2. main がシステムブラウザを開く（PKCE + localhost コールバック）
    3. 認可コードを受け取り、access_token / refresh_token を取得
    4. refresh_token を安全に保持（main のみ）
    5. そのアカウントが触れる Firebase / GCP プロジェクト一覧を API で取得
    6. ユーザーが projectId を選ぶ
    7. connectFromGoogle で Admin SDK を初期化し、接続プールへ載せる


================================================================================
プロジェクト一覧
================================================================================

  - Cloud Resource Manager / Firebase Management API 等で一覧取得
  - 「その Google アカウントが扱えるプロジェクト」を UI に出す
  - 選択した projectId で接続する


================================================================================
Firestore 接続（credential）
================================================================================

  既存:
    admin.initializeApp({ credential: admin.credential.cert(serviceAccount) })

  追加（イメージ）:
    google-auth-library の UserRefreshClient 等から credential を作り
    admin.initializeApp({ credential: ..., projectId })

  または admin.credential.refreshToken(...) 系で同等の入口を用意する。

  接続後:
    getFirestore(projectId) / ensureWritable / 既存 IPC はそのまま


================================================================================
永続化（workspace との関係）
================================================================================

  WorkspaceEntry に足すもの:
    authType          … 'serviceAccount' | 'google'
    serviceAccountPath … 既存（JSON のとき）
    googleAccountEmail … 表示用
    googleAccountKey   … google_oauth_tokens / google_profiles のキー

  ※ refresh_token は workspaces.json に直書きしない。
    config/google_oauth_tokens.json（暗号化可）に main のみが保持。

  プロファイル（config/google_profiles.json）:
    - アカウント単位で label / color / readOnly / lastFocused を保持
    - 「切断」しても残す（表示設定のバックアップ）
    - 再ログイン・再取り込み時に復元する

  切断（Google / JSON 共通）:
    - 接続だけ切る（名簿は残す → リストから再接続できる）
    - Google も token は残す（リスト再接続用）。登録解除で名簿から外し、不要なら token 破棄
    - プロファイルは残す（クラウドデータは消さない）

  再ログイン:
    - 権限のあるプロジェクトを一括取り込み・接続
    - プロファイルがあれば表示設定を復元
    - lastFocused（または接続可能な先頭）を focus


================================================================================
UI
================================================================================

  接続（メインパネル / File メニュー共通）:
    - リスト接続 … workspaces.json の登録済みを1件選んで接続（他の接続は外す）
    - JSON 接続 … サービスアカウント JSON を指定して接続（既存 Google 分は消さない）
    - Google 接続 … サインイン → 権限プロジェクトを一括で開く（現状どおり）

  左 PROJECTS:
    - 接続中（loaded）のプロジェクトだけ表示
    - 登録済みだが未接続のものは「リストから接続」側に残る

  複数プロジェクト同時接続は可（Google 一括、またはサイドバー内の追加）。
  インポートは接続とは別（メニューに残す。接続済み／登録済みへのデータ追加）。
