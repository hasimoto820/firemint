
9. ログ



@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@


方針決定。実装は分割。

1発目: 済み
　logs/ + firemint_app_*（日次・5MB・14日削除）+ logger 寄せ + 設定からログフォルダを開く
　productName / app.setName を FireMint に揃え

2発目: 済み
　firemint_job_*（Imp/Exp / Transport / Emulator 共通）
　進捗・スキップ path・完了サマリを画面下部 + ファイルへ

「ログ」は3種類に分かれる。9 番でやるのは下の2本だけ。

1. アプリログ … 開発者・問い合わせ用（接続失敗、Firestore エラー、起動情報）
2. 操作ログ … ユーザー向け（Imp/Exp / Transport / Emulator 等の長い処理）
3. 監査ログ … 誰がいつ何を変更したか → 対象外（後回し）


--------------------------------------------------------------------------------
置き場所（共通）
--------------------------------------------------------------------------------

Electron の userData 配下。

　<userData>/logs/

Windows の例:

　C:\Users\<ユーザー>\AppData\Roaming\FireMint\logs\

macOS:

　~/Library/Application Support/FireMint/logs/

ユーザーが探すとき、末尾が **FireMint/** になること。
dev / 本番とも app.setName('FireMint') + electron-builder productName: FireMint。


--------------------------------------------------------------------------------
ファイル（同じ logs/ 階層・名前で分ける）
--------------------------------------------------------------------------------

　firemint_app_YYYY-MM-DD.log … アプリログ（shared/logging/logger.ts から追記）
　firemint_job_YYYY-MM-DD.log … 操作ログ（Imp/Exp / Transport / Emulator / Script 等）

同じフォルダ・別プレフィックス。サブフォルダには分けない。

サイズ上限を超えた同日分:

　firemint_app_2026-08-27.log
　firemint_app_2026-08-27_2.log
　firemint_app_2026-08-27_3.log
　（job も同じ）

console への出力は今どおり残してよい（dev 用）。
ファイルは問い合わせ・事後確認用。


--------------------------------------------------------------------------------
ローテーション / 保持
--------------------------------------------------------------------------------

・1日1ファイル（日付はローカル日付）
・ファイルサイズ上限 5 MB。超えたら同日の続き（_2, _3 …）を新規作成
・14日より古い firemint_app_* / firemint_job_* は削除（起動時などで掃除）
・圧縮（gzip 等）は無し


--------------------------------------------------------------------------------
1. アプリログ（firemint_app_*）
--------------------------------------------------------------------------------

・今: logInfo / logWarn / logError → console + firemint_app_*
・形式: タイムスタンプ + レベル + `[firemint:<tag>] message` + detail
・出さない（サニタイズ）:
　メールアドレス
　絶対パス全文（ファイル名だけ残す）
　エラーのスタックトレース（ファイルには message / code のみ。console にはスタック可）
　トークン・秘密鍵（もともと出さない）

今はやらない:
　アプリ内ログビューア
　settings の logLevel 切替


--------------------------------------------------------------------------------
2. 操作ログ（firemint_job_* + 画面下部）
--------------------------------------------------------------------------------

・今: script_runner の appendLog → 画面下部 + firemint_job_*
　Imp/Exp / Transport / Emulator（いずれも startScriptJob）
・進捗: フェーズ切替 or 約10%ごとにログ行（path 付き）
・完了: 成功 N / スキップ M のサマリ。スキップ例は path ごと
・UI 保持: 直近 400 行。ファイルは全行（日次・5MB・14日）

Diff は未接続。長いログの「コピー」「保存」は後からでも可。


--------------------------------------------------------------------------------
UI（最小）
--------------------------------------------------------------------------------

・設定ウィンドウの下に「ログフォルダを開く」1 項目
　パスは設定を開いた時点で表示。押すとエクスプローラーで開く
　アプリ内ビューワーは作らない（今回）
　ユーザーはそこから .log をメモ帳などで開く


--------------------------------------------------------------------------------
対象外
--------------------------------------------------------------------------------

・操作監査ログ（変更履歴の永続）
・main ログの i18n（001_020_016）
・ジョブログパネルのレイアウト変更（001_054 で分割済み。高さは触らない）
・圧縮（gzip 等）
・Diff のジョブログ（短い）


--------------------------------------------------------------------------------
実装の順
--------------------------------------------------------------------------------

1発目: 済み（logs/ + firemint_app_* + logger 寄せ + ログフォルダを開く + FireMint 名）
2発目: 済み（firemint_job_* + 進捗・スキップ・サマリ）


--------------------------------------------------------------------------------
今ある / これから
--------------------------------------------------------------------------------

今:
　FireMint/logs/firemint_app_YYYY-MM-DD.log
　FireMint/logs/firemint_job_YYYY-MM-DD.log
　設定 → ログフォルダを開く
　Imp/Exp / Transport / Emulator の画面下部 + job ファイル

これから（任意）:
　ログのコピー／保存ボタン
　Diff を同じ枠に載せる


--------------------------------------------------------------------------------
漏れ
--------------------------------------------------------------------------------

1. 「ログフォルダを開く」→ 決定（済み）
2. productName → FireMint → 決定（済み）
3. 日付の境界 → 決定（済み）
